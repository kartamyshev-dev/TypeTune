# Независимый аудит покрытия локальных функций

Уточнение после аудита: appAutomatic и совместимый Settings decoder реализованы;
Chromium plain paste получает native команду после release handshake. На425e44e3
проверены15 ограниченных native cases, [STATUS](STATUS.md). Ниже сохранены исходные
находки аудита; их source identity историческая, а не актуальная приёмка.

Проверено чтением исходников и сохранённых наблюдений 2026-10-15. Это аудит
реализации, а не новая native-приёмка и не доказательство полного соответствия
Caramba. Идентичность прочитанных файлов:
[`coverage-audit-source-identity.json`](../research/evidence/coverage-audit-source-identity.json).
GUI, процессы переключателей, личные базы, настройки и REA-сессии не менялись.
Исходники могут измениться после этого аудита: ниже указаны имена методов,
чтобы не переносить выводы автоматически на последующий diff.

## Отмена, сброс и обучение

- **Реализация F14:** `KeyboardService.transaction` хранит только одну
  подтверждённую замену. `undo()` предварительно обнуляет транзакцию и принимает
  только текущий полный `after`-снимок. После отказа повторная попытка уже
  недоступна. Это установленное поведение кода; не доказанная ошибка относительно
  оригинала. Положительный сценарий: auto → ⌘⌥Z возвращает текст/источник и
  сохраняет исключение. Отрицательный: внешний edit не откатывается. Граница:
  transient AX failure на первой отмене, повторная отмена, потеря разрешения,
  многокомпонентное исправление typo+ё, выбранный диапазон и исходный источник.
- **Обучение:** все немануальные причины, включая `.userRule`, `.typo`, `.yo`,
  после успешной отмены попадают в один case-insensitive learnedWords. В самой
  функции нет раздельных политик. Нужны отдельные опыты оригинала для каждой
  причины и restart; нельзя переносить наблюдение auto на ё/typo/rule.
- **Сброс F15:** `resetTransient` очищает cachedSnapshot, transaction, жесты и
  отложенный source; вызывается на смене приложения, mouse и ряде событий.
  В пределах одного приложения нет отдельного observer смены окна/поля;
  полная identity проверяется при операции. Проверить нужно и отказ замены,
  и отсутствие потери собственных перехваченных нажатий. Положительный: возврат
  в неизменённое поле после паузы; отрицательный: другое поле/окно/PID;
  граница: смена поля в течение selection/insertion/replay каждого этапа.
- **Точный повтор событий:** `Replay` поддерживает лишь text, boundary,
  backspace, reset (последний стирает весь тестовый текст). В нём нет движения
  курсора, выделения, смены окна/поля/источника, modifier gestures, Undo и
  задержек. Поэтому успешный offline replay не покрывает эти состояния GUI;
  для них нужны native fixtures либо отдельная расширенная модель событий.

Источники: `KeyboardService.resetTransient/handle/apply/undo/finishMutation`,
`Engine.Settings/decide/manual`, `Replay.run`, `Store.learn`.

## Сохранение настроек и восстановление

`Store` хранит settings.v1 JSON (включая learnedWords), corrected,
customSoundPath, useSystemDictionary; тема хранится отдельно через AppStorage,
автозапуск — через SMAppService. Явной миграции settings.v1 и резервного
восстановления при decode failure нет: используется `Settings()`.

Особенно важно при добавлении новых полей: synthesized `Decodable` у `Settings`
требует присутствие нового non-optional ключа, даже при начальном значении
свойства. Старый сохранённый JSON тогда не загрузится целиком. Нужен отдельный
decode с `decodeIfPresent ?? default` либо версия/миграция. Это архитектурный
риск изменения формата; текущая неповреждённая версия v1 не объявляется сломанной.

Необходимы независимые проверки: полный roundtrip всех полей; старый JSON без
нового ключа; пустой/повреждённый JSON, неизвестные будущие поля; restart после
learn/remove/rule edit; путь удалённого sound-файла; реальный вход с автозапуском.
Существующий selftest проверяет один roundtrip `Settings`, а не эти сценарии
`Store` и жизненный цикл приложения. Нельзя закрывать persistence по одному
успешному сохранению темы.

## Дополнительные кандидаты F17/F18

**F17 — исправление двойной заглавной.** Функция уже частично присутствует
в `Engine.decide`, но скрыта внутри F02 и зависит от settings.typos: первые
две буквы uppercase, все оставшиеся lowercase и lower-форма есть в словаре.
Отдельного переключателя нет. `SelfTest` содержит ПРивет, HEllo, HTTP, iPhone
и off. Исследованный оригинальный pipeline (`RESEARCH`, 0x1002e10b4) выделяет
double-caps отдельной стадией и проверяет first2uppercase+thirdlower.
Найденное имя caramba_double_caps само по себе не доказывает UI-переключатель.
Следующие сценарии: ПРивет→Привет; HTTP/iPhone сохраняются; три буквы,
смешанный регистр после третьей, неизвестное словарю имя, независимость от typo.
До наблюдения оригинала нельзя объявлять текущую более строгую политику ошибкой
или отдельную настройку обязательной.

**F18 — switch_to_en_on_focus.** Имя встречается в модели special_behaviors
(`RESEARCH`, engine-marker locations); код LayoutPilot при активации приложения
лишь сбрасывает/снимает контекст, принудительный English per-app отсутствует.
Это кандидат, а не подтверждённая пользовательская функция. Нужны адресные
REA-связи поля с reader и действиями TIS, затем UI/config наблюдение. Проверки:
переход в настроенное приложение ставит English; обычный focus сохраняет
источник; возврат, несколько окон и Secure Input. Пока поле нельзя повышать
до обязательной функции без установления применимости и управляющей настройки.

## Что блокирует заявление о полном покрытии

1. Не завершён полный обход локальных поверхностей оригинала; исходный
   `ui-observations.json` содержит settings tiles и вкладки исключений,
   но не поэлементный inventory каждого диалога/меню/first-run.
2. Реестр F01–F16 смешивает функциональные категории с возможностями интерфейса;
   double-caps требует явной подстроки/ID, дополнительные кандидаты — статуса
   «не подтверждено», а не тихого включения в реализованное.
3. На текущем e1c52501 есть ограниченная Chrome native-проверка; исторические
   TextEdit smoke, автозапуск UI и корпус другого бинарника не становятся
   приёмкой всех сценариев текущего кода. Composer Codex ещё не принят.
4. `COMPARISON` явно фиксирует неидентичные версии helper и авторский корпус;
   независимый holdout, равные условия оригинала, correction-only p95 и
   30-минутный прогон текущего кандидата не закрыты.

Чекбоксы PLAN этим аудитом не отмечались. Он проверил соответствие утверждений
исходникам и выделил конкретные проверки; runtime PASS не добавлялся.
