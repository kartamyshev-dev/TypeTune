# Native-проверка TextEdit

Помощник Tools/NativeProbe.swift разрешён пользователем для новых локальных
документов TextEdit. Это синтетические CGEvents на HID-уровне; проверка не выдаётся
за физический ввод человека. Управление клавишами через UI-драйвер не запускало
глобальный tap, поэтому ранние UI-попытки не оцениваются как ошибка переключателя.

На каждое событие проверяются разрешения, Secure Input, frontmost PID, точный URL
нового документа, AX-окно и поле. При временно отсутствующем AXDocument помощник
до 300 мс повторяет только чтение при том же PID/окне/поле; другой документ или
фокус немедленно останавливает ввод. Результат атомарно сохраняется после каждого
случая. Исходный источник восстанавливается при завершении/ошибке.

## Метод сравнения

1000 примеров выбраны до измерений из synthetic-v2 (700/300, группировка сохранена).
Это ограниченная выборка из собственного словаря, не независимый языковой корпус.
Пять batches по 200; физические клавиши, исходная раскладка и ожидания одинаковы.
После каждого случая документ очищается и источник устанавливается заново.
Оригинал и прототип никогда не перехватывают ввод одновременно.

```
python3 scripts/run_native_corpus.py --target original --start 0 --batches 5 --run-id NEW-ID
python3 scripts/run_native_corpus.py --target prototype --start 0 --batches 5 --run-id NEW-ID
```

Не перезаписывать evidence; при остановке выбрать новый run-id и начать с первого
неполного batch. Частичные checkpoints не смешивать с полными без проверки ID.
Текущая точка продолжения в STATUS.

Время boundaryObservation включает ввод разделителя, чтение AX и ожидание.
Это **не** задержка исправления и не основание для критерия p95 +50мс.
Сравнение с авторским expected показывает различия требований; исходный продукт
также может отличаться от этих ожиданий. Не подбирать правила по holdout.

## Границы прототипа

AX-запросы исполняются в отдельной последовательной очереди после возврата callback перехвата. Перед изменениями очередь проверяет актуальность ревизии через главный поток; главный поток не ожидает AX IPC. Автооперация требует
подтверждённого снимка поля перед разделителем, точного ожидаемого текста после
него и того же диапазона курсора. При слишком быстром вводе снимок может не
успеть обновиться: исправление безопасно пропускается. Ручные клавиши привязаны
к последнему подтверждённому снимку; при изменении текста/фокуса операция
пропускается с сообщением. Это сознательное ограничение, не полная эквивалентность
Caramba. Обычная ⌘Z передаётся редактору; собственная отмена — ⌘⌥Z.

AX API не предоставляет атомарную compare-and-swap транзакцию: проверки до/после
снижают риск гонок, но сами по себе не доказывают отсутствие всех гонок. Тесты
в остальных приложениях и длительный прогон отмечаются отдельно.

## Барьер входящих событий

Пока AX меняет выделение и текст, клавиши (включая keyUp и модификаторы),
нажатия/перетаскивание мыши и прокрутка задерживаются только для исходного
приложения. После проверенной замены или проверенного отката они воспроизводятся
однократно с исходным Unicode и флагами. При наличии буфера раскладка не меняется;
сам буфер не запускает повторные жесты/эвристики. При внешней смене приложения
его новый ввод проходит; прежний задержанный ввод удерживается в RAM.

Если статус сообщает о задержанном вводе, вернуть прежнее поле в подтверждённое
состояние и нажать ⌘⌥R. Перед началом replay проверяется прежнее поле. У уже отправленных глобальных
CGEvents нет атомарной привязки к AX-полю: смена фокуса во время доставки
пакета отдельно не проверена и остаётся открытым ограничением.
⌘⌥Esc возвращает настройки из удерживаемого поля. Настройки позволяют явно отказаться от задержанных событий через диалог.
Обработанный нормальный ввод и буфер не записываются на диск. Аварийное завершение
не сохраняет RAM-буфер. Ограничения мягкого тайм-аута и overflow описаны в DECISIONS.
Реальные проверки на быстром вводе должны быть привязаны к окончательному SHA;
наличие кода и компиляция не являются native PASS.

## R01: обнаруженная перестановка при выпуске буфера

2026-10-15 искусственная задержка выделения 80 мс, 20 потоковых примеров:
5/20 точных ожиданий, обнаружены `hello → lhelo` и `привет → вприет`.
Файлы: native-final-stream-delayed.json, native-pre-fifo-identity.json,
native-stream-regression.json. Это **не PASS**. Исправление: не снимать барьер,
пока все воспроизведённые события не прошли tap; новые аппаратные события
ожидают следующего FIFO-блока. Повторные проверки описаны ниже; ранние результаты не переносятся на новые бинарники. Предыдущие 13 коротких примеров этого риска не выявляли.

Диагностический ключ `test.axSelectionDelayMilliseconds` считывается при старте;
отсутствует по умолчанию, значение ограничено 150 мс. Он нужен только для
воспроизводимого пересечения набора и AX-замены. Перед основной сравнительной
выборкой ключ удаляется и приложение перезапускается. Задержка не включается
обычным интерфейсом и не используется в поставляемом штатном запуске.

R01 повторён на отдельном источнике replay с токеном пакета: 20/20 сохранность,
18/20 полные исправления, два пропуска первого слова (stream-0/12). Трасса
native-fifo-fresh-source-trace.json показала 52 исходных tagged события и
8 событий с двумя собственными 64-битными токенами; stale helper tag больше
не возвращается в очередь. В старом опыте helper отправил 52 события, listener
увидел 59 с тем же helper tag. Выбор другого уровня posting сам по себе
проблему не исправлял; решающим стало назначение собственного CGEventSource
с userData пакета. Поставка использует session posting и ACK через тот же tap.

Ручное действие сразу после открытия документа может пропускаться при отсутствии
подтверждённого снимка. Нельзя засчитывать manualUndo только по совпадению
конечного текста с начальным: helper теперь фиксирует beforeGesture и промежуточную
замену. native-final-manual-undo-source.json показал отсутствие промежуточного
действия (не PASS). В варианте с явным предварительным вводом пробела
(native-final-manual-undo-source-primed.json) наблюдены hello → руддщ → hello,
а исходная RussianWin сохранена после отмены. Это подтверждает exact-source undo
для данного сценария и не устраняет ограничение первого ручного действия.

## Завершённая длительная сессия

native-session-final-fifo: 2170,29 секунды (36мин10сек), сначала 1000 сравнительных
случаев, затем 167 фраз из 16 чередующихся слов. Между случаями — ограниченная
очистка документа/установка источника; это синтетическая сессия, не 36 минут
физического ввода человека без пауз. Все 167 фраз прошли oracle порядка/числа
слов и допустимых исходных либо исправленных форм; 104/167 совпали с полным
ожиданием исправлений. У 63 фраз есть безопасно сохранённые неисправленные слова.

1080 снимков ps с шагом около2сек, максимальный разрыв2,071сек; исходный PID
жив после окончания. scripts/verify_native_session.py проверил непрерывность.
Медиана CPU29,1%, пик52,3%; peakRSS115056KiB (112,36MiB).
Медиана RSS первых30сек109952KiB, последних30сек58464KiB. Это наблюдение одного
нагруженного прогона, не доказательство отсутствия утечек; CPU требует оптимизации.
Не выводить correction-only p95 из этих измерений и boundaryObservation.

## Независимая проверка сохранности сравнительного корпуса

Новые запуски `run_native_corpus.py` после каждой пачки отдельно проверяют
фактический текст каждого ID: допустимы только точный исходный текст из
`synthetic-v2.jsonl` с завершающим пробелом либо точный `expected` из
`native-v1.json`. Исходный текст означает возможный пропуск исправления,
а не PASS качества. Любой другой результат классифицируется как
`unknown/unsafe`, без неподтверждённого утверждения о причине; пачка сохраняется
с `corpusIntegrity.unknownIDs`, `status=failed`, и следующая не запускается
для прототипа. Для original неизвестные результаты только записываются:
они являются предметом сравнения, поэтому этот oracle не останавливает baseline.

Идентичность обоих файлов фиксируется SHA-256 и проверяется до и после ввода.
Согласованность ID и авторского ожидания между файлами обязательна.
`verify_native_session.py` заново перечитывает все 1000 фактических результатов,
пересчитывает этот oracle и проверяет зафиксированные хеши, не доверяя
`passed`, `matchesExpected` или списку ошибок в summary.

Offline-проверки: `scripts/test_native_integrity.py` — 15 проверок пустого,
дублированного, переставленного, повреждённого текста, пропуска разделителя,
полного raw/expected, ID и идентичности fixtures; `scripts/test_native_evidence.py`
— 17 проверок, включая независимый отказ на пустом фактическом corpus row
при чистом summary и на изменённом хеше synthetic source. Старые отчёты
без этой привязки остаются историческими и не получают новый PASS.
Эти offline-проверки не подтверждают работу GUI или качество исправлений.
