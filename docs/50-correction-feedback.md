# 50 — предложения исключений с защитой от случайного жеста

Дата: 2026-09-16. Base `18f366ed58ddb08799e527f0d4599a0bcf513f29`
+ незакоммиченные этапы 40–50. Ubuntu 26.04.1, GNOME Shell 50.1,
Wayland, GTK 4.22.4. Основной установленный backend — compatibility evdev/uinput.

## Поведение

Одна ручная отмена не создаёт исключение. После **трёх отдельных** случаев
«автозамена → Double Shift возвращает исходный текст» появляется предложение.
Повторное переключение уже обработанного слова не считается новым случаем.
Учитывается точное обратное преобразование, завершившееся не позднее 10 секунд
после автозамены, без нового ввода, перемещения каретки и потери контекста.
Нажатие другой клавиши, reset, pause/reload/focus invalidation отменяют связь.
Неудачная или неопределённая замена не создаёт запись об успешной отмене.

«Предложения исключений (N)…» в главном окне открывается только пользователем.
В меню TT количество показывается рядом с «Открыть TypeTune». Нет автоматического
открытия окна, диалога поверх печати или перехвата фокуса. В списке есть:

- **Добавить** — добавить исправленную форму слова в существующий список
  «Не исправлять», сохранив остальные пользовательские слова и исключения.
  Как и остальные словарные исключения, оно защищает исходное слово и результат
  в обоих направлениях. Регистр не учитывается. Double Shift остаётся доступен.
- **Отклонить** — оставить словарь без изменений и не предлагать эту же пару
  снова до перезапуска runtime.

Счётчики, пары слов и предложения хранятся **только в памяти текущего runtime**.
Перезапуск/смена режима начинает новый сбор. До 64 разных пар; при переполнении
вытесняется самая старая. После 64 отклонений сбор новых предложений прекращается
до перезапуска. Постоянным становится только подтверждённое исключение в words.json;
его можно удалить через «Слова и исключения».

## Реализация и контракты

`correction_feedback.py` — ограниченные Feedback/Tracker без файлового I/O.
Счётчик увеличивается только после завершения обратной замены. Общий controller
обслуживает `suggestions-get` и `suggestions-resolve` (id/backend/action через stdin).
Решение проверяет актуальный UUID предложения, загружает свежий словарь, сохраняет
под generation lock и применяет существующим ReloadWords с generation readback.
Ошибка apply явно сообщается; устаревшее предложение ничего не записывает.
Повторное принятие после частичного сбоя не дублирует запись.

Обычный GetStatus сообщает только количество, без слов. Слова выдаются отдельным
GetSuggestions при открытии списка. Их не пишем в журналы, диагностические counters,
CLI status или evidence. Кандидаты и счётчики до подтверждения на диск не сохраняются.
GUI выполняет controller-запросы в worker; physical input callback не делает I/O.

## Границы backend

Compatibility связывает отмену с inferred history и `injected-unverified` результатом
транспорта: это не подтверждение реального содержимого поля. Его прежние ограничения
на selection, sensitivity, composition остаются. Сброс контекста обрывает связь.

IBus adapter использует `completed` после readback и хранит связь в экземпляре
редактора. Reset/focus/source invalidation очищает её; в частности, GNOME смена IBus
источника может разорвать связь между автозаменой и обратным жестом. Перенос через
смену экземпляра engine не реализован: предложение в этом случае не накапливается.
Это консервативный отказ, а не подтверждённая поддержка feedback во всех IBus полях.

## Пользовательская проверка

В пустом поле редактора/браузера, не исключённого из автоматики:

1. EN → `ghbdtn` → пробел; после «привет » сразу Double Shift → «ghbdtn ».
2. Наберите следующее новое `ghbdtn ` и повторите возврат. Выполните всего три раза.
3. Откройте TT → TypeTune → «Предложения исключений (1)…».
4. Для тестового слова можно нажать «Отклонить»: автокоррекция не изменится.
   «Добавить» сохранит «привет» в «Не исправлять»; затем его можно удалить вручную.

Один возврат, обычные ручные переключения без предшествующей автозамены и многократный
Double Shift на одном слове не должны создавать предложение.
