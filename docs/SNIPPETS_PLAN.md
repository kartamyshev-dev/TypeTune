# План: сниппеты

Цель пользователя (2026-10-18): TypeTune — универсальный помощник для ввода текста, а не
только исправитель раскладки. Первый шаг — сниппеты: короткое сокращение заменяется
текстом в любом приложении. Идеи взяты из espanso ([ESPANSO_RESEARCH](ESPANSO_RESEARCH.md)),
код и данные — свои (espanso под GPL-3.0).

Статус: **S1–S7 реализованы; S8 PARTIAL/FAIL, не закрыт**. Текущий native-стоп — многострочная вставка Chrome после двух неудачных кандидатов исправления. Решения S0 приняты пользователем 2026-10-18
(все рекомендации таблицы ниже) — DECISIONS п. 28.

## Что получится

- Пользователь задаёт сокращение и текст: `спс` → «спасибо», `;адр` → адрес,
  `;подп` → подпись в несколько строк.
- В тексте можно использовать дату, время, содержимое буфера обмена и место, где
  встанет каретка.
- Сокращение срабатывает и в другой раскладке: `$flh` в английской раскладке — тот же `;адр`.
  У espanso такого нет.
- Регистр переносится: `Спс` → «Спасибо», `СПС` → «СПАСИБО».
- ⌘⌥Z возвращает набранное сокращение.
- Вкладка «Правила» становится вкладкой «Сниппеты», прежние правила переносятся без потерь.

Окно поиска и формы — следующие отдельные планы (раздел «Дальше»).

## Из чего строится

| Есть сейчас | Как используется |
| --- | --- |
| `UserRule` + `Settings.rules`, вкладка «Правила» | Частный случай сниппета: замена целого слова на границе. Переносится в новую модель |
| `TypedWordBuffer` | Источник набранного текста для распознавания сокращения |
| `KeystrokeEditPlan`, `KeystrokeEditor`, барьер `MutationSession` | Удаление сокращения и набор короткого текста, задержка ввода во время правки, ⌘⌥Z |
| Сохранение и возврат буфера обмена (`copySelection`) | Основа вставки длинного и многострочного текста через ⌘V |
| `Layout.convert`, `Layout.matchingCase` | Сокращение в другой раскладке, перенос регистра |
| `UsageStatistics` | Новая категория: сколько символов сэкономили сниппеты |

Сниппеты работают только через универсальный режим. Ядро (S1–S4) можно делать и
проверять на Linux сейчас. GUI (S5–S7) — только после native-приёмки универсального
режима (U8): обе функции используют один буфер и один способ правки, и при
одновременной отладке не понять, какая из них ломается.

Ветка: `snippets` от `universal-input`.

## Решения пользователя (S0) — приняты 2026-10-18

| # | Вопрос | Рекомендация |
| --- | --- | --- |
| 1 | Когда срабатывает сокращение | Есть два режима. «Сразу» — сразу после последнего символа, как в espanso. «По границе» — после пробела (Return и Tab сбрасывают буфер, см. DECISIONS п. 28). По умолчанию для сокращения с начальным знаком (`;адр`) — «сразу», для обычного слова (`спс`) — «по границе» |
| 2 | Обязательный префикс (`;`, `/`) | Не обязателен. В редакторе подсказка: «начните со знака, чтобы сокращение не совпало со словом». Если сокращение — обычное слово в режиме «сразу», показать предупреждение |
| 3 | Где хранить | Отдельный `snippets.json` в Application Support, с номером версии формата. Не в UserDefaults вместе с настройками (`settings.v1`): сниппеты бывают большими, их импортируют, экспортируют и копируют отдельно |
| 4 | Объединить с «Правилами» | Да. Правило переносится в сниппет режима «по границе» с переносом регистра. Поведение не меняется, старые настройки читаются |
| 5 | Когда вставлять через буфер обмена, а не набирать | Текст длиннее 100 символов или с переводом строки — через ⌘V. Короче — набор событиями, как исправление раскладки |
| 6 | Поля, которые не читаются через AX | Работать вслепую, как исправление раскладки (DECISIONS п. 26), но только если буфер знает границу перед сокращением. Сокращение в режиме «сразу» с начальным знаком граница не нужна |
| 7 | Синтаксис переменных | `{{дата}}`, `{{дата:dd.MM.yyyy}}`, `{{время}}`, `{{буфер}}`, `{{курсор}}`. В редакторе вставляются кнопками, вручную набирать не нужно |
| 8 | Включено по умолчанию | Да. Пустая библиотека ничего не меняет, перенесённые правила работают как прежде |
| 9 | Импорт из espanso (YAML) | Позже, отдельным этапом S9. Зависимость или свой разбор подмножества YAML — решить тогда |

Чего в первой версии не будет: shell и скрипты в переменных (выполнение команд
из текста — риск безопасности), форматированный текст и картинки, онлайн-каталог пакетов.

## Этапы

Ядро (S1–S4) проверяется на Linux: CLI selftest, сборка ядра. GUI (S5–S7) — сборкой
в CI на macOS и `runtime_recovery_probe.sh`, затем вручную на Mac (S8). Каждый этап —
отдельный коммит с evidence в `research/evidence/snippets-sN-…/verification.json`.

- [x] **S1. Модель и хранение (Core)** — Linux offline, selftest 1462/1462, движок и приложение
  ещё не используют — [evidence](../research/evidence/snippets-s1-2026-10-18/verification.json).
  Экранирование `\{{` → буквальные `{{` для перенесённых правил. `Snippet`: id, сокращение, текст, режим
  срабатывания, другая раскладка вкл/выкл, перенос регистра вкл/выкл, приложения
  (все / только / кроме), включён. `SnippetLibrary`: чтение и запись JSON с версией,
  проверка (пустое или повторяющееся сокращение, длина сокращения 2–64, текст до
  10 000 символов, из управляющих только `\n` и `\t`), перенос из `Settings.rules`.
  Повреждённый файл не перезаписывается: как с настройками (`settingsStorageAvailable`),
  сохранение блокируется до явного решения пользователя.
  Проверки: чтение и запись, перенос правил с сохранением id, отказ на каждый вид
  ошибки, повреждённый файл.
- [x] **S2. Шаблон (Core)** — Linux offline, selftest 1522/1522 —
  [evidence](../research/evidence/snippets-s2-2026-10-18/verification.json). Разбор по Unicode-скалярам:
  комбинируемый знак после `{{` или `}}` не прячет скобки. Регистр меняется только в тексте, не в переменных. Разбор `{{…}}` в части: текст, дата и время с форматом,
  буфер обмена, курсор (не больше одного). Подстановка через внедряемые часы, буфер
  обмена и локаль, поэтому проверки детерминированы. Результат — текст и сдвиг
  каретки от конца в графемах. Неизвестная переменная — ошибка с позицией для
  редактора, а не молчаливая пустая строка. Пустой или нетекстовый буфер обмена —
  сниппет не срабатывает (а не вставляет пустоту).
- [x] **S3. Распознавание (Core)** — Linux offline, selftest 1566/1566 —
  [evidence](../research/evidence/snippets-s3-2026-10-18/verification.json). Пауза и исключённые
  приложения проверяет вызывающий код (S6). `SnippetMatcher` по `TypedWordBuffer`:
  - «сразу»: буфер оканчивается сокращением, всё оно набрано клавишами после сброса;
  - «по границе»: завершённый токен равен сокращению;
  - левая граница: перед сокращением пробел или известное начало, если сокращение
    начинается с буквы;
  - другая раскладка: сравнение с `Layout.convert` сокращения по физическим клавишам,
    включая знаки верхнего ряда (`;` в русской ПК-раскладке — другая клавиша);
  - перенос регистра через `Layout.matchingCase`;
  - при нескольких совпадениях — самое длинное сокращение; сниппет важнее
    исправления раскладки; исключённые приложения и пауза действуют.

  Это fixtures в selftest, включая отрицательные: `адрес` не срабатывает на `адр`,
  сокращение после клика не срабатывает вслепую, два сниппета с общим началом.
- [x] **S4. План правки (Core)** — Linux offline, selftest 1604/1604 —
  [evidence](../research/evidence/snippets-s4-2026-10-18/verification.json). Отдельный `SnippetEditPlan`;
  после вставки буфер пуст с причиной `.inserted` (окно отмены), вставленные слова не исправляются. Расширение `KeystrokeEditPlan` или отдельный
  `SnippetEditPlan`: число Backspace для сокращения (граница в режиме «по границе»
  сохраняется, как у espanso), текст, сдвиг каретки стрелками влево, способ вставки
  (набор или ⌘V по решению 5), ожидаемый текст перед кареткой для сверки AX.
  Обратный план для ⌘⌥Z: только если каретка стоит в конце вставки; при `{{курсор}}`
  сначала вернуть её вправо. После вставки буфер не должен заново исправлять
  слова из вставленного текста: последний токен помечается как «вставлен», либо
  буфер сбрасывается после ⌘V.
- [x] **S5. Вставка через буфер обмена (GUI)** — сборка и CI на macOS, native NOT_RUN — [evidence](../research/evidence/snippets-s5-s7-2026-10-18/verification.json). `SnippetEditor` + `ClipboardSwap`. `PasteInserter`: сохранить все типы
  (общий код с `copySelection`), записать текст с пометками `org.nspasteboard.TransientType`
  и `org.nspasteboard.ConcealedType`, чтобы менеджеры истории его не запоминали.
  Дождаться отпускания модификаторов, отправить ⌘V в pid. Сверить через AX, если
  поле читается. Вернуть прежнее содержимое после задержки (у espanso 300 мс),
  только если `changeCount` не менял никто другой; иначе не трогать и сообщить.
  Пробник в CI: запись, возврат, чужая запись во время операции.
- [x] **S6. Срабатывание (GUI)** — сборка и CI, native NOT_RUN — [evidence](../research/evidence/snippets-s5-s7-2026-10-18/verification.json). Ограничения: «сразу» не срабатывает на нажатиях, воспроизведённых после барьера; статистика сниппетов не ведётся; раскладка после сниппета не меняется. В `universalKeyDown`: «сразу» — после доставки
  последнего символа, «по границе» — там же, где сейчас исправление раскладки.
  Сначала ждать отпускания модификаторов, затем барьер, правка, сверка, ⌘⌥Z,
  статус «Сниппет вставлен», звук по настройке, статистика. Ни текст сниппета, ни
  сокращение не попадают в `InputDiagnostics`.
- [x] **S7. Интерфейс (GUI)** — сборка и пробник с настоящим Store 8/8, native NOT_RUN — [evidence](../research/evidence/snippets-s5-s7-2026-10-18/verification.json). Вкладка «Сниппеты» вместо «Правил»: поиск по списку,
  добавление и правка в отдельном окне (многострочный текст, кнопки переменных,
  предпросмотр с подставленной датой, режим, другая раскладка, приложения),
  включение и выключение, удаление с подтверждением. Импорт и экспорт своего JSON.
  Предупреждение, что сниппеты хранятся на диске без шифрования: не храните в них пароли.
- [ ] **S8. Проверка на Mac** — чек-лист ниже.
- [ ] **S9. Импорт из espanso** (после решения 9): подмножество `trigger`, `replace`,
  `word`, `propagate_case`, `$|$`, переменные `date` и `clipboard`. Остальное
  пропускается со списком пропущенного, без молчаливой потери.

## Риски и защита

| Риск | Защита |
| --- | --- |
| Сокращение совпало с обычным словом или его началом (`адр` в «адрес») | Режим «по границе» для слов, подсказка о префиксе, предупреждение в редакторе, правила для приложений |
| Модификаторы ещё зажаты, и Backspace читается как ⌘⌫ или ⌥⌫ | Ждать отпускания перед любой правкой ([ESPANSO_RESEARCH](ESPANSO_RESEARCH.md) п. 1) |
| Enter в мессенджере отправит сообщение | Перевод строки никогда не набирается клавишей Return: многострочный текст — только через ⌘V |
| Длинный текст набирается медленно, пользователь печатает параллельно | Порог для ⌘V; барьер задерживает новый ввод |
| Приложение читает буфер обмена позже | Возврат прежнего содержимого с задержкой и проверкой `changeCount` |
| Сниппет вставил текст, а буфер потом «исправил» последнее слово вставки | Вставленный текст не исправляется (S4) |
| Конфиденциальный текст в сниппетах | Без записи в диагностику; пометка Concealed при вставке; предупреждение в UI |
| Поле пароля | Secure Input и `AXSecureTextField` отключают всё, как сейчас |
| ⌘⌥Z после того, как каретка ушла внутрь вставки | Отмена только при сверке, что перед кареткой ожидаемый текст; иначе «Нет актуального сниппета для отмены» |

## Чек-лист S8 для Mac

Проводится после U8, по правилам AGENTS.md, другие переключатели не запущены.

1. `спс ` → «спасибо » и `Спс ` → «Спасибо »: TextEdit, Заметки, Safari, Chrome, Telegram, Slack,
   VS Code, Word, Terminal (zsh).
2. `;адр` в режиме «сразу» в тех же приложениях; `$flh` в английской раскладке.
3. Многострочная подпись через ⌘V: строки на месте, сообщение в Telegram не отправилось,
   прежний буфер обмена (текст и картинка) вернулся, в Maccy нет лишних записей.
4. `{{дата}}` и `{{курсор}}`: каретка стоит в нужном месте.
5. `{{буфер}}` с картинкой в буфере обмена: сниппет не срабатывает.
6. ⌘⌥Z сразу после вставки возвращает сокращение.
7. Быстрый набор сразу после сокращения: порядок символов не нарушен.
8. `адрес ` при сниппете `адр`: ничего не вставлено.
9. Поле пароля и `sudo` в Terminal: ничего не происходит.
10. Перенесённые правила из прежних настроек работают как раньше.
11. В конце восстановить раскладку, настройки и буфер обмена.
