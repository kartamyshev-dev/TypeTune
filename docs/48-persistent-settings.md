# 48 — Сохранение настроек и автозапуск

2026-09-16. Base `18f366ed58ddb08799e527f0d4599a0bcf513f29` + этапы 40–48.

## Поведение

Режим (compatibility/IBus) и состояние автокоррекции сохраняются автоматически.
Выбор режима в остановленном окне меняет настройку для следующего запуска;
явный запуск конкретного backend через controller также запоминает его.
Меню индикатора запускает сохранённый режим. Пауза временная, до явного старта
или следующего входа; «Остановить» не отменяет автозапуск на последующие входы.

В GUI добавлен switch «Запускать при входе в систему», изначально выключенный.
Он создаёт/удаляет пользовательский XDG autostart entry для GNOME. Окно показывает
подтверждённое наличие правильного entry, а не только намерение из JSON.
При несовпадении предлагается выключить/включить switch для восстановления.
Закрытие GUI по-прежнему оставляет TT в панели при доступном SNI host.

Настройки: `$XDG_CONFIG_HOME/typetune/settings.json`, отдельно от words.json.
Обновления отдельных полей под writer lock, атомарная замена и fsync содержимого.
Save + runtime SetAutomatic сериализованы одним settings lock; при ошибке apply
сообщается «сохранено, но не применено». Показанное значение в работающем режиме
берётся из runtime; в остановленном — из сохранённой настройки.
Runtime читает automatic при старте, до обработки событий. Повреждённые настройки
не заменяются defaults на диске; auto при старте такого runtime выключен, status
показывает ошибку. Stop продолжает работать независимо от валидности настроек.

## Автозапуск

Entry: `$XDG_CONFIG_HOME/autostart/dev.kartamyshev.TypeTune.Preview.desktop`,
`OnlyShowIn=GNOME`, установленный controller с командой `autostart`.
Включение сначала готовит launcher, затем сохраняет flag; ошибка записи откатывает
launcher. Выключение сначала сбрасывает flag, затем удаляет entry. Команда запуска
проверяет flag, поэтому оставшийся при ошибке удаления entry не включает runtime.
Uninstall удаляет entry, сохраняет пользовательские файлы настроек/слов.

Команда ждёт готовый user-session bridge без lock/shield/overview максимум 45 секунд,
перечитывая настройку. Повторная login-команда защищена неблокирующим lock;
уже работающий runtime не перезапускается и не снимается с паузы.
Stop во время ожидания ставит cancel marker; выключение autostart тоже отменяет
ожидание. После начала запуска backend не повторяется вслепую при ошибке.
По истечении ожидания открывается GUI со статусом, controller завершается с ошибкой.
Индикатор запускается без открытия окна при успешном восстановлении.

## Пользовательская проверка

Включите «Запускать при входе в систему». При следующем входе ожидается индикатор
TT и сохранённая настройка автокоррекции. При отсутствии bridge проверьте статус
в окне; повторная установка/вход могут требоваться для самого GNOME расширения.
Автозапуск использует тот же opt-in compatibility профиль и его ограничения;
он не расширяет гарантии password/selection или список принятых приложений.

## Подтверждение пользователя

После этого стенда пользователь включил автозапуск и подтвердил в разговоре:
«проверил, после перезагрузки компьютера, автозапуск работает».
Это acceptance его текущего GNOME/compatibility сеанса; прочие desktops,
IBus при входе и восстановление после сбоев ещё требуют отдельных проверок.
