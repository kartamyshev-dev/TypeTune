Evidence и ARM64 инструкции из `deep-evidence-bundle.json` и
`phase2-evidence-bundle.json`, затем новый сохранённый `phase3-evidence-final.json`
(89 records). Этот worker новую сессию Ghidra не запускал. UI, ввод,
процессы и настройки не менялись. Runtime-проверок этот документ не заявляет.

Индекс: [undo-research-findings.json](../research/evidence/undo-research-findings.json),

private bundle. Target arm64 SHA-256:
`19d0057a9bfc38ba590babff82b28b5bf496c0833bbbd221f502722c6e2a26e9`.

Таким образом, прежние три недостающих адреса получены, но причинная связь
`Backspace/отмена → additions/visible/disabled → save` по-прежнему не установлена.

## Что пока нельзя утверждать

Из этих Evidence нельзя вывести, что одно нажатие Backspace восстанавливает
слово или немедленно обучает исключение. Уменьшение буфера может дойти до нуля
после нескольких удалений; конкретный набор переходов требует восстановления.
Нельзя связать `additions`, `visible`, `disabled` с числом отмен или конкретным
порогом. В исследованном dispatch и новых пяти телах прямого Core Data setter
для этих полей нет; недоисследованный model-метод либо callback может скрывать путь.
Это ограниченный отрицательный результат, не доказательство отсутствия обучения.

`⌘⌥Z → learnedWords` LayoutPilot остаётся самостоятельным контрактом.
Его успешный тест не доказывает соответствие Undo/learning Caramba. Известные
ручные UI add/remove исключения, отдельно проверенные координатором, также
не устанавливают автоматическое обучение после отмены.

## Точные недостающие процедуры

1. **`0x1002e0030`** — feature extraction ниже уже полученного
   `0x1002dfac8`. Последний проверен псевдокодом и ASM: перебор records0x28,
   sentinel и flagbit0 → Boolean; прямого persistence нет. Evidence:
   `ev_70b49bff3fb0ad93b1bcb4ff0a0680aa1628299bdc778e0d003917dea54696bd`,
   `ev_1c06051f78df1ee083cc8c9186c36d52b88ad8de0d3fd47376a43c8254fc8c32`.
   Полный смысл категорий и вызываемых ниже операций пока не установлен.
2. **`0x10024b614`** и используемые строковые helpers — определить единицу
   и результат начальной проверки `0x100255a14`/`0x1002e35bc`; восстановленный
   ABI не даёт права автоматически называть её числом символов.
3. **`0x1002df1a0`** и initialization refs matcher-объектов — установить
   семантику filters без публикации или переноса оригинальных шаблонов.

После этого нужен переход к фактическому writer `AutoswitchExceptionsStore`,
его callers и изменениям `additions/visible/disabled`. Адрес такого writer в
прочитанных Evidence **не установлен**, придумывать его по имени строки нельзя.
Повторный импорт оригинала для уже сохранённых функций не требуется.

Для последующей runtime-проверки использовать отдельный синтетический документ:
известное автоисправление → Backspace один раз → повторное Backspace/возврат
слова → повтор исходной ошибки → restart → повтор. Для каждого шага фиксировать
текст, раскладку и **только синтетическую** строку собственной добавки в backup.
Отдельно проверить ручное исправление и отказ от предлагаемого добавления.
До выполнения этих опытов F14 и общий checkbox полноты остаются открытыми.
