# Поведение функций и границы продукта

## Уточнение пользователя от 2026-09-16

Основной ручной жест — двойное короткое нажатие одного Shift: исправить последнее
слово и переключить язык **дальнейшего ввода**. Повторный Double Shift после
завершения замены должен снова преобразовать это слово и вернуть соответствующую
раскладку; каждый жест — новая ручная операция. Это явное уточнение прежней политики
ручного исправления без смены источника. Автокоррекция нужна общесистемно.
Текущая реализация и ограничения: [checkpoint 36](36-auto-shift-checkpoint.md).
Остальные требования ниже сохраняются как целевой продукт, не обещание готовности.

Статус: целевая спецификация от 2026-09-10, а не описание уже работающей версии. Реальное состояние — в [аудите функций](12-feature-audit.md). Архитектурные контракты — в [документе 13](13-target-architecture.md).

Текущее поведение исключений приложений: [этап 49](49-application-exclusions.md).
Точный desktop ID запрещает только автоматическую коррекцию; ручной Double Shift
сохраняет прежние проверки. При непустом списке неизвестное приложение запрещает
автозамену. Применение настроек требует runtime generation ACK.

## 1. Продуктовая цель и порядок функций

TypeTune помогает исправлять ошибочную раскладку, вставлять часто используемый текст и, на поддерживаемом Linux-оборудовании, компенсировать дребезг клавиш. Пользователь должен понимать, что сейчас включено, почему замена не сработала и как её отменить. Обычная печать должна оставаться отзывчивой при выключенных функциях, ошибке словаря и медленном шаблоне.

| Приоритет | Функция | Ценность / граница |
|---|---|---|
| P0 | Надёжный ввод, pause, понятная диагностика | Основа до добавления автоматизации |
| P1 | Ручная коррекция текущего/последнего слова | Предсказуемое исправление без догадки словаря |
| P1 | Статические Unicode-сниппеты | Реальная экономия времени, одинаковый engine на ОС |
| P1 | Профили приложений и ограничений | Автозамена работает только там, где её поведение проверено |
| P1 Linux opt-in | Настраиваемый anti-chatter по устройству | Не влияет на клавиатуры без проблемы |
| P2 | Консервативная автокоррекция RU/EN | После принятой ручной коррекции и качественных словарей |
| P2 | Date/time, условная отмена последней замены, пользовательский словарь | Удобство без внешних команд |
| P3 | Shell-шаблоны, поиск/выбор сниппета, расширенная типографика | Отдельные проверки worker/контекста/конфликтов |
| Позже | Выделенный текст, новые пары раскладок, синхронизация | Требуют отдельного дизайна и возможностей backend-а |

Это рекомендуемый порядок реализации, основанный на текущих дефектах. AI-автокоррекция, облачная обработка ввода и загрузка произвольных плагинов не входят в этот план.

## 2. Коррекция раскладки

### Ручной режим

Команда исправляет текущее слово перед кареткой либо последнее завершённое слово с известным delimiter, пока context epoch не изменился. Без достоверной истории — ничего не удаляет. Пример: `ghbdtn` → `привет`, `ghbdtn ` → `привет `; слово слева до этого фрагмента сохраняется.

Исправление использует соответствие клавиш двух **конкретных** раскладок. Это не языковая транслитерация. Системная раскладка после замены остаётся прежней, если пользователь не выбрал отдельную явно поддерживаемую команду переключения. Сложные сочетания AltGr/dead key/IME требуют собственного профиля; таблица стандартных US↔RU не описывает все раскладки мира.

Сохранение регистра: lowercase → lowercase; Titlecase → Titlecase; UPPERCASE → UPPERCASE. Смешанный регистр — посимвольное преобразование в ручном режиме при однозначном mapping; в автоматическом режиме неоднозначный token пропускается.

Double Shift — опциональный gesture из двух полных последовательных taps одной и той же Shift-клавиши, без других клавиш, мыши и смены фокуса между ними. Нажатие/удержание Shift для заглавной буквы не считается tap. Время берётся из нормализованного потока, а не времени работы matcher-а. Разные Shift-клавиши одновременно не создают команду. Тестировать конфликт с системными accessibility shortcuts; разрешить выбрать другой shortcut или отключить gesture. В observer-режиме TypeTune не обещает скрыть эти Shift-события от ОС.

### Автоматический режим

Включается явно для поддержанного профиля. На границе слова engine рассматривает кандидат и заменяет лишь при высокой уверенности по правилам:

1. Текущий token неизвестен словарю исходной раскладки.
2. Перекладка даёт известное слово целевого словаря и не содержит неоднозначных преобразований.
3. Длина достаточна; обе раскладки и контекст известны.
4. Нет признаков URL, email, пути, кода, mixed script, числового идентификатора или исключённого приложения.
5. Нет активного точного сниппета на тот же диапазон, composition и устаревшего контекста.

Если обе формы валидны, ни одна не известна или язык не RU/EN — автозамены нет. Короткие слова и имена по умолчанию обрабатываются консервативно. После пользовательской отмены не исправлять тот же token снова в текущем контексте. Пользовательское исключение/добавление слова — отдельная явная настройка.

Word boundaries описать отдельно от mapping. Символы `[`, `]`, `;`, `'`, `,`, `.` на US-клавиатуре могут соответствовать русским буквам; жёсткое правило «вся пунктуация завершает слово» теряет такие кандидаты. Observer MVP использует **только Space**. Enter/Tab допускаются позже лишь при подтверждённой вставке текстового newline/tab в том же поле либо отдельном контракте удержания action-key. Enter может отправить сообщение, Tab — сменить поле; после такого действия коррекция не выполняется. Пунктуационные boundaries вводятся после corpus tests. Delimiter учитывается ровно один раз.

Текущий срез коротких слов: [checkpoint 42](42-two-letter-correction.md) —
две буквы при цели в top-100, три — в top-1000; известное исходное слово сохраняется.
Однобуквенные слова исключены из автокоррекции.

Текущий feedback: после трёх отдельных точных возвратов автозамены в течение
10 секунд предлагается исключение. Только явная кнопка «Добавить» сохраняет его;
счётчики и отклонения действуют до перезапуска. После трёх отдельных ручных
исправлений завершённого слова (пробел до или после жеста) предлагается добавить целевое слово для
автокоррекции. Повторные жесты на одном слове отменяют обучение.
[Актуальное поведение и проверки этапа 53](53-dictionary-suggestions.md).

### Словари

Штатные файлы по 10 000 строк нельзя считать валидированными словарями: audit обнаружил отсутствие демонстрационных `hello`/`привет` и искусственные формы. До включения автоматической коррекции:

- Указать источник, версию, лицензию, преобразования, checksum и правила нормализации.
- Проверить UTF-8, пустые/повторные строки, script, словоформы, частотность и ошибки генерации.
- Разделить системный словарь и пользовательские исключения; не писать изменения в пакетные файлы.
- Иметь curated corpus: positive examples, valid words, имена, аббревиатуры, URL/code, ambiguous tokens и punctuation-mapped слова.
- Отдельно измерять false corrections и пропущенные исправления. Целевой приоритет — минимизация ошибочных замен, а не максимальное число замен.

Отсутствующий/повреждённый словарь отключает автоматическую коррекцию с причиной; ручная коррекция и печать продолжают работать. Молчаливый пустой словарь не считается успешной загрузкой.

## 3. Сниппеты

Начальный контракт: trigger с prefix, например `:date`, завершённый Space. Сам trigger и пробел уже видимы приложению; executor заменяет весь соответствующий суффикс и сохраняет пробел один раз. Расширение configurable delimiters подчиняется тем же ограничениям Enter/Tab, что и коррекция; несовместимый delimiter отвергается при настройке профиля. Режим без delimiter может появиться отдельно и не смешивается с этим счётом удаления.

Требования matcher-а:

- Явные Unicode/регистровые правила и ограничение длины trigger/replacement.
- Детерминированный приоритет: exact full trigger, longest match при применимости; одинаковые конфликтующие triggers отклоняются при загрузке.
- Word boundary зависит от конфигурации. Внутри `abc:date` стандартный сниппет не срабатывает.
- Backspace обновляет достоверную историю, navigation/focus change/unknown edit сбрасывают её.
- Выключение, reload и замена очищают устаревший matcher state.
- Сниппет имеет приоритет перед автокоррекцией на пересекающемся диапазоне; собственный replacement не запускает match повторно.

Renderer выдаёт `String` либо ошибку. Он не генерирует keycodes, не удаляет trigger и не возвращает усечённый текст для неизвестных символов.

Начальные переменные: `date` и `time` через библиотеку календаря, с определённым timezone/format. Зафиксировать leap year, границу месяца/года, часовой пояс и переход локального времени в тестах. Форматирование даты приближением «год = 365 дней» недопустимо.

Shell templates — поздний opt-in механизм. Шаблон компилируется однократно; stdout команды становится обычными данными и не парсится снова как `{{shell:...}}`. Указать interpreter/argv, timeout, output size limit, exit status и cancellation. Команда исполняется от session user, не helper/root; ошибка сохраняет исходный trigger. Пользователь видит, какие entries выполняют команды. Backend без подходящего shell сообщает limited capability, а не запускает неявный другой интерпретатор.

## 4. Anti-chatter: физический автомат

Область первой реализации — выбранные Linux-устройства. Функция выключена по умолчанию до индивидуальной настройки. Глобальное окно 50 ms не является доказанной универсальной настройкой; оно способно съедать намеренные быстрые повторы. Модификаторы по умолчанию не задерживаются фильтром, пока не приняты отдельные shortcut tests.

### Предлагаемый базовый алгоритм

Выбрать **release debounce** с немедленной выдачей первого Down и отложенной выдачей Up. Это проектный компромисс: буква появляется сразу, отпускание задерживается на настроенное окно. Параметр подбирается на записанном тестовом trace; произвольное число в документации не является профилем оборудования.

Для `(device_id, key)` хранить physical state, output state и optional release deadline. Начинать с согласованного neutral state; при resync действовать по transport-контракту.

| Состояние | Событие | Действие |
|---|---|---|
| Up | Down | Немедленно output Down, перейти Down |
| Down | повторный Down без Up | Подавить дубликат; не создавать второе удержание |
| Down | Up | Запомнить deadline, перейти PendingRelease; output пока Down |
| PendingRelease | Down до deadline | Отменить pending Up; продолжить одно удержание |
| PendingRelease | deadline истёк, физически Up | Output Up, перейти Up |
| Up | лишний Up | Не выдавать orphan release; diagnostic counter |
| Down, физически Down | Repeat | Пропустить по единой repeat policy; не считать chatter |
| Невозможная/утраченная последовательность | Например Repeat после известного physical Up | Diagnostic + state reconciliation; не угадывать новое нажатие |

Один serial scheduler согласует входные frames и таймеры. При пробуждении сначала забрать уже готовые input frames в bounded backlog, обработать их в определённом порядке source time/sequence и лишь затем истёкшие deadlines, которым не предшествует непрочитанное событие из этого backlog. При равенстве времени Down и deadline выбрать правило «Down отменяет pending release» и закрепить тестом. Пример: Up@100, deadline120, Down@110 уже в очереди, helper проснулся@130 — выдавать Up до чтения Down нельзя. Превышение лимита backlog/потеря временной достоверности требует resync/degraded, а не бесконечного drain или произвольной перестановки.

При обработке события с timestamp строго после deadline сначала выполнить относящийся к нему таймер, если очередь более ранних событий уже разобрана. Повторные Up в PendingRelease не сдвигают deadline бесконечно. Таймер работает в быстром helper-е независимо от engine/UI/shell. Окно 0 означает identity mode с учётом согласованного состояния.

Такой алгоритм подавляет пары `Down→Up→Down` в окне, в том числе bounce после длинного удержания. Намеренное быстрое повторное нажатие в том же окне будет объединено — без дополнительной информации оно неотличимо от bounce. Это необходимо показать при калибровке и измерить на повторных буквах/игровом вводе. Если задержка Up неприемлема, alternative mode и его ограничения оформляются отдельным ADR, а не скрытой сменой алгоритма.

Задержанный output Up может продлить autorepeat, который делает desktop/client, даже если kernel Repeat обработан верно. Кроме того, последующий Ctrl/Shift может пересечься с ещё логически удерживаемой буквой. Базовая flush policy: перед новым Down другой клавиши завершить pending releases с уже известным physical Up в этом seat, сохранив реальное multi-key удержание. Это уменьшает артефакты, но не доказывает отсутствие дополнительного repeat до нового Down. Обязателен native тест physical Up непосредственно перед repeat deadline. Если артефакт неприемлем и backend не может управлять repeat, ограничить/отклонить профиль или пересмотреть алгоритм по ADR; release debounce пока остаётся гипотезой для прототипа, а не принятой аппаратной реализацией.

Lifecycle-переходы различаются:

- Reload параметров сохраняет physical/output pressed-state. Уже назначенные deadlines завершаются по старой generation; новые используются для следующих циклов.
- Disable фильтра переводит в identity: pending Up выдаётся, где physical Up известен; настоящие удержания остаются до настоящего Up. Само отключение алгоритма не требует ungrab посередине удержания; detach helper-а выполняется отдельно.
- Disconnect освобождает только output ownership исчезнувшего устройства, отменяя его timers; удержания других устройств сохранены.
- Stop/detach использует neutral-state/reconciliation протокол транспорта, а при аварии сообщает границы потери состояния.

Не подавлять release только потому, что «похожий press был недавно»: физический и уже выданный output state должны оставаться согласованными.

Статистика: физические Down/Up/Repeat, подавленные повторные edges, объединённые циклы, discarded observations, latency и выбранный профиль устройства. Счётчик «подавлено событий» не равен числу исправленных букв. Хранить агрегаты без текстового лога.

## 5. Настройки, профили и диагностика

Пользователь видит состояние каждой функции: включена и работает; выключена; недоступна; работает с ограничением. Причины конкретны: нет разрешения, layout неизвестен, backend не видит focus, словарь не загружен, требуемый способ вставки недоступен.

Pause прекращает новые text actions и сбрасывает history. Hardware filter управляется отдельно: пользователь может временно отключить коррекцию, оставив anti-chatter. Аварийная остановка helper-а — отдельное действие с определённым neutral-state переходом.

Профиль приложения использует стабильный application identity, доступный backend-у, а не только изменчивый title. Title filters — дополнительная возможность. При невозможности проверить профиль не применять его разрешающие правила ко всем приложениям.

GUI сохраняет изменения атомарно и учитывает generation: устаревшее окно не перезаписывает чужие свежие правки. После Apply отображается ответ runtime-а, включая `restart-required`; успешная запись файла не называется успешным применением. Неверный конфиг не должен блокировать stop, doctor, version и исправление файла.

Будущий `doctor` показывает версии/backend, capabilities, доступы, список выбранных устройств, config path/generation, dictionary provenance/count и последние ошибки без текста. Отдельный добровольно включаемый trace mode предназначен для синтетического тестового ввода, ограничен по времени и никогда автоматически не загружается наружу.

## 6. Что считается кроссплатформенным MVP

Единый engine/config format и одинаковые accepted scenarios для ручной коррекции и статических сниппетов в заявленных профилях Linux, Windows, macOS. Необходимы native tests и установка, а не только сборка common crates.

Полная поддержка IME, всех password fields, всех редакторов, hardware debounce на всех ОС и любых Wayland-композиторов не обещается. UI/CLI обязан корректно сообщить эти границы. Типографика, исправление выделения и сложные динамические шаблоны расширяют принятый механизм replacement, а не создают новые независимые цепочки Backspace/keycodes.
