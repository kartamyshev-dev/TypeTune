# Текущее состояние macOS input backend

Checkpoint: 2026-10-07, кандидат 0.2.7, Apple Silicon/macOS 27.0.1.

Production использует активный HID/head tap и вывод через session stream.
Неизменяемая таблица активной раскладки готовится на главном потоке и обновляется
при TIS notification; callback получает snapshot без обращения к TIS или AX.
История связывается с предполагаемым foreground PID. Это снимок активного
приложения, а не документированная маршрутизация раннего HID-события.

Вывод использует combined session source и согласованные Unicode/flags на обоих
краях клавиши. Очередь до 256 событий сохраняет следующий ввод. Общий срок
транзакции — 100 мс; первый отложенный ввод ограничивает удержание 50 мс.
Смена приложения, Secure Input, потеря tap, переполнение и stale revision
останавливают недостоверную транзакцию. После неизвестного результата повтора нет.

Enter, навигация, pointer и shortcut сбрасывают историю и разрешают новый ввод.
Разрыв наблюдения в том же приложении, включая пустой batch, требует известной
границы слова; сброс вспомогательного FocusHistory не снимает этот запрет.
Старый annotated/AX/carrier путь сохранён для регрессионных fixture, но не
используется RuntimeEnvironment.live. AX-текст и свойства поля production
не читает; результат отправки — submitted, постоянное обучение по нему запрещено.

## Границы и продолжение

Нативные результаты относятся к диагностической сборке. Submitted не проверяет
текст редактора; неизвестно число всех ожидаемых пользователем исправлений,
поэтому 8 операций не являются измерением success rate. Есть unmatched Shift-up
records, причинно не привязанные к конкретному намеренному жесту.

Матрица приложений и физические sleep/wake/lock сценарии: NOT_RUN.
Программное изменение поля без ввода не обнаруживается; произвольные custom
secure fields не классифицируются. Подпись ad-hoc может потребовать повторного
согласия при следующем обновлении. Новую сборку нельзя считать нативно принятой
на основании проверки подписи, CI или результатов другой identity.
