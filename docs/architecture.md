# Архитектура

## Слои

```text
┌─────────────────────────────────────────────────────────┐
│  UI (GTK tray / macOS menu bar)                         │
│  один controller, generation ACK настройки              │
└───────────────────────────┬─────────────────────────────┘
                            │ configure / status
┌───────────────────────────▼─────────────────────────────┐
│  typetune-bridge  (JSON ABI, protocol)                  │
│  gesture, history, anti-loop, learned words             │
└───────────────────────────┬─────────────────────────────┘
                            │ plans / suggestions
┌───────────────────────────▼─────────────────────────────┐
│  typetune-engine                                        │
│  layout mapping, frequency scoring, snippets, guards    │
└─────────────────────────────────────────────────────────┘

Platform adapters (не смешивать с engine):
  Linux  — passive evdev/uinput + session helper
  macOS  — HID CGEvent tap + session output + Text Input Source
```

## Принципы

1. **Физический ввод и текстовые правки — разные контракты.** Обычные нажатия сразу идут приложению. Во время короткой macOS-транзакции следующие события удерживаются в ограниченной очереди; callback не обращается к движку, Accessibility, диску, UI или раскладкам.
2. **Один план замены — один исполнитель.** План использует непрерывную наблюдавшуюся историю; потеря событий запрещает замену неполного слова. Подготовленные события согласуют физический код, модификаторы и Unicode целевой раскладки. Production macOS не проверяет текст и диапазон редактора через AX.
3. **Свои события помечены.** Синтетические клавиши не считаются новым пользовательским вводом и не запускают коррекцию по кругу.
4. **Unknown ≠ успех.** Неизвестный фокус, selection, composition, чувствительность поля или раскладка не притворяются подтверждённой безопасностью. После неопределённого результата **нет** слепого повтора.
5. **Смена раскладки — явное действие.** Движок получает фактически прочитанную раскладку, включая отказ и откат. Первое авто-слово после внешней смены пропускается согласно настройке; собственная успешная правка не подавляет следующее слово.
6. **Приватность.** История — только RAM. Диагностика записывает результаты, причины и длительности, без отдельных клавиш, слов и clipboard.

## Коррекция (engine)

| Режим | Триггер | Решение |
|---|---|---|
| Manual | Double Shift | Перекладка последнего слова (без требований словаря) |
| Auto | Space (граница слова) | Ratio-скоринг частотных словарей + охрана URL/кода/регистра |

Таблица соответствия — посимвольная US ↔ Русская (ПК), **не** транслитерация. Сложные раскладки, AltGr и dead keys — вне таблицы.

## Bridge protocol 3

JSON-операции (урезанно): `configure`, `dictionary_update`, `key_event`, `edit_result`, `layout_notice`, `learned_add` / `learned_clear`, `reset_context`, `prepare` / `smart` / `authorize` / `observe`, `infer`.

`edit_result` различает `verified` (текст и каретка прочитаны и совпали), `submitted` (события отправлены без подтверждения текста), `failed_before` / `rejected` и `unknown_after` / `indeterminate`. Прежний `ok` сохраняет совместимость истории, но не разрешает постоянное обучение. Неверный ID, время вне срока и ошибки ACK сбрасывают контекст без повторной отправки.

Подтверждённый результат может добавить необязательный `feedback` с `learned_add` и `exclusions_add`. macOS сохраняет дельту через проверку поколения настроек. `dictionary_update` принимает `words`, `learned`, `exclusions`, подтверждается `dictionary_updated` и сохраняет историю/жест, позволяя немедленный обратный Double Shift. Поле `key_event.manual` необязательно и по умолчанию включено для старых клиентов.

Лимиты ABI: вход ≤ 512 KiB, ответ ≤ 32 KiB; превышение отменяет транзакцию без retry.

## Платформенные границы

| | Linux | macOS |
|---|---|---|
| Наблюдение | evdev (без exclusive grab) | активный HID/head tap, вне транзакции пропускает события |
| Вывод | отдельное uinput-устройство | session CGEvent (keycode / modifiers / Unicode / Backspace) |
| Раскладка | session helper / compositor | Text Input Source API + readback |
| Контекст текста | keymap-inferred (limited) | история физических клавиш; AX-текст/выделение не читаются |

Неизвестные capabilities остаются Unknown в статусе UI.

## Транзакция macOS

План привязан к событию, ревизии ввода и предполагаемому foreground PID. Раннее HID-событие переводится через immutable mapping активной раскладки: TIS/UCKeyTranslate выполняются на главном потоке, callback использует готовый snapshot. Подготовка вывода и ожидание отпускания клавиш проходят до `begin`. Разрешения проверяются в runtime; повторные запросы TCC не выполняются во время удержания ввода.

Транзакция имеет очередь до 256 событий и общий срок `operationDeadline` — 100 мс от `begin`. Первое перехваченное событие физического ввода запускает отдельный бюджет удержания 50 мс. Действующий срок равен минимуму общего срока и времени первого события плюс 50 мс; следующие события его не продлевают. Независимый watchdog проверяет срок и Secure Input, освобождая очередь при отмене. Позднее завершение проверки не разрешает вывод в уже закрытой транзакции. Эти сроки задают бюджеты исполнения, а не гарантию точности планировщика macOS.

После выбора раскладки, непосредственно перед выводом проверяются срок, актуальность транзакции, foreground PID и Secure Input. Подготовленный пакет отправляется через session stream из main/output очередей, вне HID callback. AX-поле и его свойства не читаются: программное изменение текста или каретки без событий ввода может остаться незамеченным. Старый annotated/AX/carrier путь остаётся в регрессионных fixture.

Обычный новый ввод не прерывает начавшуюся замену: клавиши и отпускания воспроизводятся по порядку после неё, а текст согласуется с установленной целевой раскладкой. Pointer, shortcut и смена адресата отменяют удержание и сразу пропускаются. Это транзакция доставки событий, а не атомарная операция текстового редактора.

Переполнение, потеря tap, смена цели и тайм-аут освобождают отложенный ввод и инвалидируют историю. После неизвестного результата повтор запрещён. Enter, навигация, pointer/shortcut и реальная смена приложения разрешают свежую историю; наблюдательный разрыв в том же приложении требует известной границы слова. Результат production macOS — `submitted`, без проверки текста и постоянного обучения. Разрешения обязательны; системный Secure Input останавливает обработку, произвольные custom secure fields через AX не классифицируются.

## Настройки и диагностика macOS

`~/Library/Application Support/TypeTune/settings.json` хранит schema v2 и числовой `generation`: авто/ручное переключение, активные TIS-источники, политику слов, выученные формы и исключения. Старый v1 мигрирует при чтении. Атомарная запись защищена межпроцессной блокировкой и сравнением поколения; обновление словаря отдельно от общих настроек не сбрасывает текущий жест.

`diag.log` записывается асинхронно: очередь до 256 записей/64 КиБ, текущий файл до 1 МиБ и одна ротация `diag.log.1`. Файлы имеют права `0600`; прежний журнал сохраняется как `diag-legacy-*.log`. `--doctor` показывает идентичность сборки и разрешения отдельного диагностического процесса; наличие другого PID не доказывает здоровье его обработчика ввода.

Установщик разделяет рабочий пакет и архивы отката. Перед атомарной заменой создаётся ZIP в приватном каталоге данных, проверяемый распаковкой, подписью и сравнением содержимого. Скрытый staging не имеет расширения `.app`; старый пакет не оставляется рядом с рабочим приложением как второй зарегистрированный bundle ID. Разрешения TCC и регистрация LaunchServices установщиком не переписываются.

## Настройки (Linux)

`~/.config/typetune/settings.json` — schema v2 c `generation` ACK (uuid). Поля-тумблеры
совпадают с macOS `Settings.swift` по смыслу: auto/manual switching, switch-only-last-word,
dont-switch-words, dont-correct-after-layout-change, display-layout-flag, play-switching-sound,
active-keyboards. Слова и исключения приложений живут в отдельных файлах с собственным
generation (`words.json`, `applications.json`).

Политика передаётся в bridge через `configure.policy`; `infer` учитывает её
(`layout_only` при `dont_switch_words`). Внешняя смена раскладки вызывает `layout_notice`
и пропускает **одно** авто-слово (анти-петля).
