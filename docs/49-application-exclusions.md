# 49 — исключения приложений в GUI

Дата: 2026-09-16. Checkout: `18f366ed58ddb08799e527f0d4599a0bcf513f29`
с накопленными незакоммиченными этапами 40–49.

## Результат

Кнопка **«Исключения приложений…»** открывает список установленных desktop applications
с поиском по имени/идентификатору и флажками. Отмеченные приложения исключены только
из **автокоррекции на пробеле**. Double Shift продолжает работать в пределах возможностей
выбранного backend. Один desktop ID распространяется на все окна приложения.
Список по умолчанию пуст: терминалы и редакторы пользователь выбирает сам.
Сохранённые, но больше не установленные приложения остаются видимыми и удаляемыми.
Поиск не сбрасывает скрытые флажки. Конфликт двух окон сохраняет черновик и сообщает ошибку.

GUI и CLI используют общий controller: `apps-get` возвращает document и каталог;
`apps-save` принимает JSON через stdin. `$XDG_CONFIG_HOME/typetune/applications.json`
хранит schema version, generation и до 500 точных desktop IDs. Запись под lock,
с атомарной заменой и fsync содержимого; ошибочный файл не перезаписывается молча.
`ReloadApplications` в обоих runtime подтверждает generation и отменяет pending plans.
Controller сверяет ACK с GetStatus. Ошибка применения отличается от успешного сохранения;
старый runtime требует перезапуска. При остановленном runtime настройки загрузятся при старте.
Файл не читается в обработчике клавиш.

## Контекст и ограничения

GNOME bridge v4 уже передаёт app_id внутри GetCompatContext/GetTextContext.
Используется desktop ID, без заголовков окна, URL и содержимого поля.
При непустом списке и неизвестном ID автоматическая замена запрещена; ручная сохраняет
прежние guards. При пустом списке действует прежняя политика явно включённого compatibility.
Повреждённый список при старте отключает автокоррекцию, но не ручной жест.
Статус различает глобальный automatic и automatic_blocked для текущего приложения.
GUI показывает причину; глобальный переключатель не сбрасывается из-за исключения.

Проверка выполняется при подготовке и перед изменением текста. В compatibility identity
связана с контекстом до/после собственного переключения источника. При смене app_id
история сбрасывается. Уже отправленный source-switch может завершиться после отмены;
атомарность source-switch и редактирования не обещается. После начала инъекции
отмена сохраняет неопределённость результата и не вызывает повторную замену.

В IBus воспроизведён regression: разрешение auto отозвано между prepare и authorize,
но редактор получал «привет » вместо сохранения «ghbdtn ». Повторная проверка auto
перед edit исправляет этот случай. Исключения не расширяют поддержку password fields,
selection, IME и других desktops. Разные упаковки одного приложения могут иметь разные
IDs; каждую нужную запись следует отметить отдельно.

## Проверки

Среда: Ubuntu 26.04.1 LTS, GNOME Shell 50.1, Wayland, GTK 4.22.4,
Python system GI; compatibility evdev/uinput, без exclusive grab.

- APPS-49-UNIT: **56 IBus/controller/GUI + 16 compatibility = 72 Python tests PASS**.
  Controlled editor проверяет исходный текст/каретку/баланс клавиш при исключении,
  ручной запрос, разрешённое приложение, неизвестную identity, смену policy/identity
  и reload до инъекции. Storage: invalid/corrupt/write failure/stale generation;
  controller: matching/mismatched ACK и старый runtime. GUI model: global/effective reason.
- APPS-49-GTK: реальный GTK picker с изолированным storage — поиск, сохранение скрытого
  выбора, повторное открытие, конфликт, удаление отсутствующего приложения PASS.
  Повторены основной GUI smoke и words editor smoke. Снимки обоих окон просмотрены.
- APPS-49-LIVE: установленный GTK → controller → compatibility generation ACK PASS.
  Реальная GNOME desktop identity временно исключена: runtime сообщил excluded-application;
  прежний список восстановлен. Auto=false и autostart=true пользователя сохранены.
- Release installation PASS, Python compile и diff check PASS. Rust не менялся;
  предыдущие 120 Rust tests относятся к этапу 47, в этом этапе не перезапускались.

[Evidence](evidence/49-applications.txt). Native ввод с исключениями в browser/editor/terminal,
IBus live application exclusion, XWayland и другие desktops на этом этапе **не приняты**.
Автозапуск после reboot отдельно подтверждён пользователем для его GNOME сеанса (этап 48).

## Проверка пользователем

1. Откройте TypeTune через TT → «Открыть TypeTune».
2. В «Исключения приложений…» отметьте браузер или текстовый редактор и сохраните.
3. Включите «Автокоррекция после пробела» (при обновлении сохранено ваше auto-off).
4. В пустом текстовом поле отмеченного приложения: EN → `ghbdtn` → пробел.
   Слово должно остаться. Double Shift должен дать «привет » и RU.
5. Снимите исключение и сохраните. Снова выберите EN и наберите новое `ghbdtn `:
   теперь ожидается автоматическое исправление. После перезапуска список сохраняется.

Следующий срез: учитывать ручную отмену ошибочной автозамены, сохраняя контекстные guards,
и расширить независимый корпус качества и native app matrix.

Пользовательская обратная связь после установки: «вроде работает». Это предварительное
подтверждение текущего приложения, без зафиксированной полной native matrix.
