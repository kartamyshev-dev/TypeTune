# Необязательный системный словарь RU/EN

`SystemVocabulary` — самостоятельно написанное расширение словаря через macOS `NSSpellChecker`. Это собственная замена словарного механизма, а не восстановленный словарь или алгоритм Caramba. В GUI переключатель «Расширять словарь средствами macOS» сохраняется отдельно; при отсутствии пользовательского значения он выключен. Базовое ядро и его тестовые корпуса этим адаптером не изменяются.

## Поведение

Адаптер работает на главном потоке. Сначала вызывает обычный `Engine.decide`; готовое решение ядра всегда имеет приоритет. Если решения нет, проверяет доступность обоих языков, флаги функций, secure/reliable-контекст, приложения-исключения, слова-исключения и обучение. Защитные условия выполняются до обращения к системной проверке орфографии.

Дополнительный путь ограничен токенами 3–40 символов и 80 единиц UTF-16. Допускаются целиком русские либо ASCII-английские буквы, а также физические клавиши с пунктуацией, если полное преобразование раскладки даёт слово из букв RU/EN. Цифры, URL, смешанные алфавиты и прочие неподдерживаемые токены не передаются системному словарю.

Признанное правильным исходное или преобразованное слово добавляется только во временную копию `Lexicon`; окончательное решение снова принимает Engine. Если исходное слово правильно, оно защищает от автоматической конверсии в другой язык. Постоянный встроенный словарь не переписывается.

Общие опечатки рассматриваются только при включённой функции, для полностью строчного исходного слова от пяти символов. Должен существовать ровно один близкий вариант того же языка на расстоянии одной вставки, удаления, замены или соседней перестановки. Неоднозначность считается до исключения вариантов с прописными буквами и ё: отбрасывание небезопасного варианта не превращает множество догадок в «единственную» замену. Кандидат повторно проверяется словарём; варианты с прописными буквами или ё не подставляются. Новые автоматические ё-правила из предложений Apple не создаются; действуют только явные правила ядра.

Кэш FIFO ограничен 4096 записями и существует только в памяти процесса. Слова и предложения не журналируются и не записываются на диск. Адаптер не вызывает `learnWord`, `setLanguage`, запись пользовательских предпочтений, показ панели проверки орфографии или собственные сетевые API. Используются отдельный документный тег и явный язык каждого запроса.

## Источник API и интерфейс

Сигнатуры и правила явного языка проверены по установленному SDK macOS 27: `AppKit.framework/Headers/NSSpellChecker.h`, методы `checkSpellingOfString:startingAt:language:wrap:inSpellDocumentWithTag:wordCount:`, `guessesForWordRange:inString:language:inSpellDocumentWithTag:`, свойства `availableLanguages`, методы управления документным тегом. SDK рекомендует передавать известный язык явно, не менять глобальный язык проверяющего объекта.

```swift
@MainActor
let provider = SystemVocabulary()
provider.isAvailable
provider.statusInfo // Состояние и счётчики; без набранных слов.
provider.decision(word, settings: settings, context: context)
```

При отсутствии RU или EN адаптер возвращает точный результат базового Engine. Текущие выбранные идентификаторы: `ru` и `en_GB`; приложение не меняет языковые предпочтения пользователя.

## Выполненная диагностика

Самостоятельный `Tools/SpellProbe.swift` использует только фиксированные синтетические примеры, не открывает документы, не активирует приложения и не посылает события клавиатуры. Ожидания составлены до первого запуска соответствующих примеров; контрольные корпуса к ним не подбирались.

Проверены **13/13** примеров: сохранение нормальных слов, расширенное исправление раскладки для «телескоп» и `microscope`, физическая пунктуация в «жонглирование», общие опечатки `microscoppe` → `microscope` и «телесккоп» → «телескоп», защитные примеры цифр, URL, смешанного алфавита, прописного имени, акронима и неоднозначной формы «сестры».

Проверены **9/9** условий: secure, unreliable, исключённое приложение, слово-исключение, обучение, все функции выключены, отсутствие системных запросов для защитных случаев, сохранение приоритета базового решения, полное использование кэша на втором проходе той же выборки.

В последнем выполненном прогоне: оба языка доступны; 13 запросов проверки орфографии и 2 запроса предложений; вся диагностика заняла 59,8 мс, наиболее долгий отдельный пример — 32,88 мс (research/evidence/system-vocabulary-probe.txt). Это наблюдение при прогретых системных сервисах, без измерения нативного потока клавиатуры. Оно не является гарантией задержки, p95, проверкой качества корпуса или сравнением с Caramba.

Команды из корня проекта после сборки debug-ядра:

```sh
swift build --product layoutpilot-cli
swiftc -swift-version 5 -I .build/debug \
  Sources/LayoutPilot/SystemVocabulary.swift Tools/SpellProbe.swift \
  .build/debug/LayoutPilotCore.o -o .build/debug/spell-probe -framework AppKit
.build/debug/spell-probe
```

Бинарник диагностики размещается рядом с `LayoutPilot_LayoutPilotCore.bundle`: запуск из другого каталога без ресурса ядра завершится ошибкой загрузки bundle. Сам диагностический код не выводит произвольный пользовательский ввод — только заранее определённые синтетические строки.

## Ограничения

- Состав, варианты языка и результаты системного словаря зависят от версии macOS, установленных провайдеров и пользовательского словаря. Наличие языков не гарантирует правильность распознавания каждого слова.
- Синхронные системные методы не имеют заданного этим адаптером жёсткого таймаута. Ограничен размер входа и работа над предложениями, но холодный запуск или задержка сервиса может занять больше наблюдавшегося времени.
- Отсутствие собственных сетевых вызовов не доказывает сетевую изоляцию всех системных либо сторонних провайдеров проверки орфографии.
- Кэш не отслеживает внешнее изменение пользовательского словаря и списка языков во время жизни экземпляра; для повторного определения доступности требуется новый экземпляр/перезапуск приложения.
- Прописные формы, имена, акронимы и неоднозначные слова обрабатываются консервативно. Общая коррекция опечаток может пропускать реальные ошибки; словарь не восстанавливает намерение автора.
- Нативный ввод, фокус, отмена и задержки приложения с включённым адаптером требуют отдельной проверки. Результаты исходного corpus baseline к этому режиму автоматически не переносятся.

Отдельная native-интеграция кандидата ae3f565: corpus/native-system-vocabulary.json,
6/6 текстов и источников в native-final-system-vocabulary.json. Проверено в TextEdit
при interval80ms/settle600ms; после опыта настройка off. Это не переносит результаты
основного сравнения на режим системного словаря и не является массовой оценкой.
