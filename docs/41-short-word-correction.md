# 41 — Автокоррекция частых трёхбуквенных слов

2026-09-16. Основание: пользовательский пример `rfr` → «как».
Base commit `18f366ed58ddb08799e527f0d4599a0bcf513f29` + изменения этапов 40/41.

## Изменение

Минимальная длина 4 исключала этот пример до проверки словаря.
Теперь длина 3 допускается только для целей из top-1000 частотного списка.
Для длины 4–32 остаётся top-20000 + pilot. Исходное слово, известное любому
из словарей, по-прежнему защищено. Слова длиной 1–2 не исправляются автоматически.
Регистр сохраняется; mixed case, код, URL и прочие ограничения не изменены.
Порог является консервативной эвристикой, не гарантией отсутствия ложных замен.

## Проверки

SHORT-41: regression сначала упал на `prefix rfr suffix`, затем прошёл.
26 случаев в controlled editor с fake clock проверяют содержимое, каретку,
selection anchor, сохранение префикса/суффикса и совпадение inferred/committed.
Примеры: `rfr`/`Rfr`/`RFR`, `xnj`, `ult`, `rnj`, `'nj`, `еру`;
неизменные `cat`, `yet`, «как», «нет», `the`, длина 1–2, редкий кандидат,
mixed case, отсутствие/двойной пробел, числа, URL/email/path/code.

117 Rust tests (workspace/all-targets/locked/offline) прошли, включая прежний
корпус из 174 случаев. Ubuntu 26.04.1, Rust 1.98.1; это simulated проверки,
новая native GUI приемка не выполнялась. [Evidence](evidence/41-short-words.txt).

## Установка и проверка

Обновлена preview библиотека, активный compatibility runtime перезапущен.
В пустом поле с US: `rfr` + Space → `как `; дальнейшая раскладка RU.
Повторный Double Shift остаётся ручным переключением независимо от словаря.
Короткие неоднозначные слова могут пропускаться; для них остаётся ручной жест.
