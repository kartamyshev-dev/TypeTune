# 47 — Слова и исключения через GUI

2026-09-16. Base `18f366ed58ddb08799e527f0d4599a0bcf513f29` + этапы 40–47.

## Пользовательский результат

В окне TypeTune появилась кнопка «Слова и исключения…» и два списка:

- **Мои слова**: известные пользователю правильные RU/EN слова. Они защищены в
  исходном тексте и разрешены как цели автокоррекции независимо от частотного порога.
- **Не исправлять**: запрет автоматической замены, если исходное слово или результат
  находится в списке. Исключения имеют приоритет над пользовательскими словами.

Одна запись на строку; регистр не учитывается, дубликаты удаляются. От 2 до 32 букв,
только один алфавит RU либо EN; максимум 500 записей в каждом списке. Фразы, пути,
код и однобуквенные слова не входят в этот срез. Double Shift остаётся независимым
от списков; остальные context guards/Space/защита известных исходных слов сохраняются.

Пример: добавьте «клавиатуры» в «Мои слова», сохраните. US `rkfdbfnehs` + Space
теперь получает цель «клавиатуры». Добавьте «привет» в исключения — `ghbdtn` + Space
сохраняется; Double Shift по-прежнему исправляет его вручную.

## Хранение и применение

`$XDG_CONFIG_HOME/typetune/words.json` (обычно `~/.config/typetune/words.json`),
отдельно от пакетных данных. Атомарная замена файла, fsync содержимого, файл 0600,
writer lock и проверка generation: старое окно не перезапишет более новую версию.
Закрытие без сохранения отменяет черновик; GUI сохраняет черновик при ошибке записи.
Uninstall не удаляет пользовательский файл.

GUI обращается к общему controller (`words-get`, `words-save`, payload через stdin,
не argv). После записи controller вызывает ReloadWords у работающих профилей
и проверяет effective generation. Runtime сбрасывает pending/history при применении;
частичная замена не повторяется. При остановленном runtime показано «применится
при запуске»; ошибка применения явно отличается от успешного сохранения на диск.

Python preferences загружаются только при старте/ReloadWords, не при клавишах.
Rust UserDictionary валидируется в ограниченном Configure запросе на semantic
границе, хранится в handle как immutable BTreeSet. Новая generation загружается
при следующем semantic запросе; configure не заменяет pending/in-flight план.
IBus и compatibility используют один Rust matcher. В обычные логи слова не пишутся.

Повреждение файла на старте отключает auto с причиной в status/GUI, manual остаётся.
Неудачный reload сохраняет последнюю рабочую generation. Runtime загрузка встроенных
частотных словарей и их лицензия этим этапом не менялись.

## Проверки

- WORDS-47-ENGINE: controlled editor + fake clock, текст/каретка/anchor/суффикс,
  custom target, защита исходного слова, исключение, inferred parity и manual override.
- WORDS-47-ABI: Configure validation; неверный словарь сохраняет старый; pending plan
  отклоняет configure и остаётся авторизуемым.
- WORDS-47-STORE: normalize/save/reload, stale generation, повреждение/лимиты,
  ошибка atomic replace без порчи старого файла, отказ runtime reload.
- WORDS-47-CONTROLLER: saved-but-not-applied и stopped/deferred статусы.
- WORDS-47-ADAPTER: IBus simulated editor и compatibility Rules на реальной C ABI:
  exclusion/manual, смена generation, custom target и auto отказ при ошибке словаря.
- WORDS-47-GTK: реальное окно с изолированным storage — save/reopen, ошибки валидации,
  конфликт параллельного редактора. Снимок fixture визуально проверен.
- WORDS-47-LIVE: установленный controller сохраняет неизменённые пользовательские
  списки, работающий compatibility подтверждает generation. После перезапуска
  та же generation загружена без ошибки. Тестовые слова в пользовательские списки
  не добавлялись; реальная коррекция в чужом поле новым словарём не проверялась.

120 Rust tests и 40 IBus/controller + 14 compatibility Python tests PASS.
Ubuntu 26.04.1 / GNOME Wayland / GTK4 / Rust 1.98.1.

Native IBus ReloadWords и реальный ввод пользовательских слов требуют отдельной приемки.

## Остаётся

Сохранение остальных переключателей, исключения приложений, автоматическое
запоминание отмены в текущем контексте и расширенный независимый корпус качества.
Этот этап реализует явное управление словами/исключениями, не закрывает весь G4.
