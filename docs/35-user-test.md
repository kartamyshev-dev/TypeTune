# TypeTune: пользовательская проверка

[Сохранение настроек и автозапуск](48-persistent-settings.md): переключатель
«Запускать при входе в систему» в окне TypeTune. По умолчанию выключен.


[Пользовательские слова и исключения](47-user-dictionaries.md) доступны через
кнопку «Слова и исключения…» в окне TypeTune; списки сохраняются и после перезапуска.


Графическое управление: откройте **TypeTune** в меню приложений.
Индикатор **TT** в системной панели позволяет открыть окно, поставить на паузу
и переключить автокоррекцию; закрытие окна оставляет индикатор.

## Установка без терминала

Готовый `.deb` откройте графическим установщиком Ubuntu. После установки откройте
**«TypeTune — настройка»** — особенно при переходе с прежней установки из checkout.
Далее настройте текущего пользователя; при первом подключении расширения нужен
повторный вход. [Подробности и удаление с сохранением настроек](51-debian-package.md).

## Предложения исключений

После трёх отдельных возвратов одной автозамены через Double Shift откройте
**«Предложения исключений (N)…»**. «Добавить» сохраняет слово в «Не исправлять»,
«Отклонить» оставляет автоматику без изменений. Окно не открывается само.
Счётчики и отклонения сбрасываются при перезапуске TypeTune.
[Точный сценарий и ограничения](50-correction-feedback.md#пользовательская-проверка).

## Исключения приложений

В окне TypeTune нажмите **«Исключения приложений…»**, найдите приложение,
поставьте флажок и нажмите **«Сохранить и применить»**. В нём перестанут выполняться
автозамены после пробела; Double Shift останется доступен. Чтобы вернуть автоматику,
снимите флажок и сохраните. Список сохраняется после перезапуска.

Если список не пуст и приложение определить не удалось, автозамена не выполняется.
Глобальный переключатель авто при этом сохраняет своё значение. Подробнее:
[поведение и сценарий проверки](49-application-exclusions.md#проверка-пользователем).


## Режим максимальной совместимости

Добавлен по вашему явному выбору; архитектурный ориентир — Espanso.
Режим читает физическую клавиатуру без grab и заменяет слово через uinput.
Не требует IBus/AT-SPI и не ограничен списком приложений. Поддерживаемая сессия:
GNOME 50 / Wayland, обычные US/RU; XWayland-поле тоже прошло стендовый тест.

При первой установке выполните команды из корня checkout. После install
**выйдите из GNOME и войдите снова**, чтобы загрузить расширение:

```sh
./scripts/typetune-test install
# После повторного входа:
./scripts/typetune-test compat-on
```

Откройте пустое поле любого редактора. В обычной US-раскладке наберите `ghbdtn`
и дважды коротко нажмите один Shift: ожидается `привет` и дальнейший русский ввод.
Для автокоррекции выберите обычную US, наберите `ghbdtn` и пробел.
После завершения замены следующий двойной Shift переключает это же слово обратно
и меняет раскладку: `ghbdtn → привет → ghbdtn → привет`. Работает и после
автокоррекции; пробел сохраняется. [Проверки повторного жеста](39-repeat-double-shift.md).

```sh
./scripts/typetune-test pause       # приостановить перед паролями/важными командами
./scripts/typetune-test resume
./scripts/typetune-test auto-off    # оставить только ручной жест
./scripts/typetune-test status
./scripts/typetune-test compat-off
```

`compat-on` включает режим явно на текущий запуск, автозапуска нет. `start` или
`browser` возвращают прежний IBus-режим и выключают compatibility.
Статус `injected-unverified` означает, что клавиши отправлены, **а результат в поле
не подтверждён**. В неизвестном поле режим не различает пароль, выделение и IME;
его нельзя считать безопасным автоматическим корректором любых данных.
При `indeterminate` проверьте поле вручную, не повторяйте замену вслепую.
Если `available: false`, проверьте обычный источник US/RU, отпущенные модификаторы,
CapsLock, lock/overview и XKB remapping. Требуется доступ к input devices и uinput;
права/группы установщик автоматически не меняет.

Полный [результат и границы проверок](37-universal-input-investigation.md).
Native tests использовали контролируемый поток событий и compositor output;
пользователь подтвердил работу физической клавиатуры в браузере после
исправления задержки ввода (этап 38). Это не приемка всех приложений. Ниже сохранена инструкция прежнего IBus-режима.

## Как проверить

1. После установки/обновления **сохраните работу, выйдите из сеанса GNOME и войдите
   снова**. Shell должен загрузить расширение v4, IBus — оба новых источника.
   Закрытия терминала недостаточно.
2. В корне проекта выполните:

   ```sh
   ./scripts/typetune-test browser
   ```

3. В открывшемся Chrome наберите `ghbdtn` без пробела. Дважды коротко нажмите
   **один и тот же Shift**, отпуская его после каждого нажатия. Получится `привет`,
   дальнейший ввод станет русским — источник TypeTune RU.
4. Для проверки автоматики выберите **TypeTune US** в меню раскладок GNOME,
   очистите поле, наберите `ghbdtn` и пробел. Получится `привет `, ввод станет русским.
5. В TypeTune RU наберите английское `hello` по физическим клавишам — увидите
   `руддщ`. Double Shift исправит его на `hello` и включит TypeTune US.

Интервал между отпусканием первого Shift и вторым нажатием — до 350 мс,
каждое удержание — до 200 мс. Поддержаны левый и правый Shift, но смешанная пара
не считается жестом. Щелчок, другая клавиша или смена поля отменяют жест.
После перехода в другое поле сначала наберите новое слово.

Страница локальная, без скриптов и отправки/сохранения текста. Chrome открывается
с отдельным профилем `~/.cache/typetune-test/chrome`, Wayland и GTK3.
Выбор источника TypeTune действует в сессии, поэтому можно пробовать другие
приложения. При отсутствии необходимых API коррекция откажет.

## Управление

Команды из корня репозитория:

| Команда | Результат |
|---|---|
| `./scripts/typetune-test install` | Собрать и установить обновление для пользователя; затем повторный вход |
| `./scripts/typetune-test browser` | Открыть отдельный Chrome с инструкцией и включить TypeTune US |
| `./scripts/typetune-test start` | Включить TypeTune US без открытия браузера |
| `./scripts/typetune-test auto-off` | Отключить автоматику, оставить Double Shift |
| `./scripts/typetune-test auto-on` | Включить автоматику |
| `./scripts/typetune-test pause` | Приостановить коррекцию, обычный ввод продолжается |
| `./scripts/typetune-test resume` | Возобновить; заново наберите слово |
| `./scripts/typetune-test status` | Установка, guards, effective state и счётчики |
| `./scripts/typetune-test stop` | Завершить runtime, убрать оба своих источника, сохранить остальные |
| `./scripts/typetune-test uninstall` | Удалить пользовательскую установку |

Автоматика включена при запуске runtime. `auto-off` действует до его завершения;
настройка пока не сохраняется между запусками. Для выхода из режима также можно
выбрать штатную US/RU через меню GNOME или Super+Space. TypeTune не захватывает
клавиатуру. Stop восстанавливает прежнюю US/RU, если ещё выбран источник TypeTune;
если вы сами сменили источник, выбранная вами раскладка сохраняется.

## Ограничения

**Поддержка всех приложений ещё не завершена.** Native acceptance выполнен для
простых полей Chrome 153 на Wayland и GNOME Text Editor 50.1 с AT-SPI.
Для других приложений нужны IBus surrounding text и проверяемый AT-SPI текстовый
контекст. XWayland, терминалы, пароли, игры и canvas-поля не приняты.
Обычный ввод в неподдерживаемом поле остаётся доступен.

Автокоррекция использует пилотный словарь: 150 RU / 149 EN слов. Исправляет только
известные преобразования после пробела; это ещё не полноценный языковой детектор.
Double Shift не требует попадания слова в словарь. Composition и произвольные
редакторы отдельно не приняты; немедленное обратное исправление после смены
источника не гарантируется. F8/F9 остались диагностическими командами без смены языка.

## Если ничего не происходит

Выполните `./scripts/typetune-test status`:

- `bridge: false`: нужен повторный вход или включение пользовательских расширений GNOME.
- `runtime: not-running`: выполните `browser` или `start`.
- `enabled: false`: выполните `resume`, наберите слово заново.
- `inactive-source`: выберите TypeTune US/RU; обычные US/RU не запускают корректор.
- `unsupported-application` / `editor-context-unconfirmed`: нет подтверждённого
  контекста. Запуск status в терминале сам переносит фокус в неподдержанное окно.
- `manual_rejected`: отказ до редактирования; наберите слово заново без выделения.
- `manual_indeterminate`: результат замены неизвестен; проверьте поле вручную,
  не повторяйте замену вслепую.
- `mode_result: unconfirmed`: смена языка не подтверждена; проверьте меню раскладок.

## Установка

Нужны Rust/Cargo и C toolchain с pkg-config; native development libraries
workspace (udev, xkbcommon/X11, GTK4 и libadwaita), системный Python 3 с GI
типами Gio/GLib, IBus и AT-SPI. Рабочая среда — GNOME Shell 50 / Wayland.
Для команды browser дополнительно нужен Google Chrome. Проверенная версия Rust —
1.98.1; минимальная версия toolchain всей текущей сборки отдельно не принята.

Installer собирает release offline. Для свежего checkout сначала загрузите
зависимости (`cargo fetch --locked`); системные библиотеки и права устройств
нужно подготовить отдельно. Ошибка сборки/доступа не должна обходиться запуском
всего приложения от root.


Файлы: `~/.local/share/typetune-test`, пользовательский IBus component XML,
GNOME extension `typetune-session@typetune.local` и
`~/.config/environment.d/90-typetune-ibus.conf`. Стандартный путь IBus сохранён.
Root, clipboard и браузерные расширения не нужны. Профиль тестового Chrome не
удаляется uninstall, чтобы не удалять сохранённые в нём пользовательские данные.

На рабочей машине bridge v4 загружен, compatibility установлен и проверен
пользователем. Новая установка на другой машине требует собственного повторного
входа и проверки.
При `ibus write-cache` установленный `ibus-engine-table --xml` выдаёт warning;
регистрация TypeTune и изолированные проверки при этом проходят.
