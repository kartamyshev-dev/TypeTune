# 51 — пакет Debian для GNOME preview

Актуальное изменение: [этап 54](54-remove-ibus.md) удаляет IBus-адаптер и его зависимости; описания IBus ниже относятся к первой версии пакета. Установка и сохранение настроек продолжают действовать.

Пакет `typetune-preview` предназначен для Ubuntu 26.04 / GNOME Shell 50.
Это текущий Python/GTK preview с готовым Rust engine и пассивным evdev/uinput helper.
Исторический daemon и его системная служба не устанавливаются.

## Установка без терминала

Откройте `.deb` в графическом установщике пакетов и подтвердите установку.
Затем откройте TypeTune в меню приложений и нажмите «Настроить TypeTune для моего
пользователя». При первой установке потребуется выход и повторный вход в GNOME.

Если у учётной записи нет доступа к клавиатуре, кнопка «Разрешить доступ к устройствам
ввода…» вызывает системный запрос пароля. Она добавляет пользователя в группу input:
это даёт всем программам этой учётной записи доступ к устройствам ввода. После изменения
группы требуется повторный вход. Пакет не добавляет пользователей в группу автоматически.

Настройку можно открыть повторно через действие ярлыка «Настроить доступ и сеанс».
Настройки в `~/.config/typetune` сохраняются при обновлении и удалении пакета.

При переходе с установки из checkout сначала откройте отдельный ярлык
**«TypeTune — настройка»**: старый пользовательский ярлык может перекрывать новый.
Настройка остановит старый процесс, перенесёт регистрацию на файлы пакета и сохранит
словари, исключения, режим и флаг автозапуска. Компиляция при этом не выполняется.

## Обновление и удаление

Новую версию `.deb` установите тем же графическим установщиком. Активный packaged
runtime останавливается перед заменой файлов. После обновления снова откройте TypeTune:
при изменении версии появится настройка сеанса. При изменении GNOME bridge нужен
повторный вход. Пакетные hooks не запускают корректор от root или за пользователя.

Удалить пакет можно через графический менеджер пакетов либо через
«TypeTune — настройка» → «Удалить TypeTune — настройки сохранятся…».
Используется системный запрос пароля. `~/.config/typetune` не удаляется даже при purge.
Активные стандартные пользовательские сеансы очищают свою регистрацию/автозапуск;
выключенные/недоступные сеансы и нестандартные XDG-пути могут сохранить файлы
регистрации. TryExec делает пакетные ярлыки/автозапуск неактивными при отсутствии пакета.
В загруженном GNOME сеансе удаление расширения полностью завершается после выхода.
Повторная установка использует сохранённые настройки при следующей настройке сеанса.

Выданное вручную членство в группе input при удалении не отзывается: оно может быть
нужно другим приложениям и могло существовать до TypeTune. Это отдельное разрешение
учётной записи, а не настройка runtime. Uninstall не удаляет неизвестную пользовательскую
установку без package_version в манифесте.

## Состав и сборка

- `/usr/lib/typetune-preview`: Python runtime/GUI, готовые `.so` и compat_transport,
  GNOME bridge payload, marker package.json, фиксированные privileged helpers.
- `/usr/bin/typetune-preview`, два desktop launcher, policy Polkit,
  правило uinput `0660 root:input`, modules-load.d uinput.
- `/usr/share/doc/typetune-preview`: лицензия проекта, FrequencyWords provenance/license
  и notices разрешённого Cargo dependency graph для текущей Linux-платформы.
- Нет системного daemon, setuid, автоматического group membership или exclusive grab.

Сборка разработчиком: `python3 scripts/build-preview-deb.py`.
Нужны build dependencies workspace, Cargo cache, dpkg-dev и Python. Для пользователя
они не нужны. Бинарные зависимости вычисляются dpkg-shlibdeps; GNOME ограничен 50.x.
Артефакт: `dist/typetune-preview_0.1.0~preview51-1_amd64.deb`.
Раздача пакета/подпись и репозиторий автоматических обновлений пока не реализованы.

## Проверки и границы

Base `18f366ed58ddb08799e527f0d4599a0bcf513f29` + незакоммиченные этапы 40–51;
Ubuntu 26.04.1, GNOME Shell 50.1, GTK 4.22.4, Wayland, amd64.

- PKG-51-UNIT: 63 IBus/controller/GUI + 18 compatibility + 2 privileged-helper
  tests = **83 Python PASS**. Migration/upgrade/unregister, сохранение пользовательского
  конфигурационного файла и прежних GNOME extension flags, отсутствие Cargo в setup,
  whitelist privileged actions и отсутствие операций с host из isolated root.
- PKG-51-DPKG: настоящий dpkg в user namespace/отдельном root: install → upgrade
  (`+test1`) → remove → purge → reinstall PASS. Проверены реальные файлы/версия,
  сохранение config fixtures, удаление runtime и desktop entry. Зависимости в пустом
  test root подавлены `--force-depends`; это не проверка чистой VM с Ubuntu.
- PKG-51-DEPS: `apt-get -s install <deb>` на текущей Ubuntu разрешает зависимости:
  только typetune-preview новый, без удаления/обновления системных пакетов.
- PKG-51-GTK: реальное окно setup с управляемыми операциями: configure/open,
  отмена системной авторизации доступа/удаления; никаких неявных привилегий.
  Screenshot собственного окна просмотрен. Основной GUI smoke PASS.
- Native системная установка с вводом пароля и полный logout/login новой пакетной
  регистрации пока требуют пользовательской проверки. Root-хуки активной сессии
  не считаются проверенными лишь по isolated-root тесту.

Rust engine не менялся, прежние 120 Rust tests не перезапускались.
[Evidence](evidence/51-package.txt).

## Найденный сбой App Center на рабочем стенде

При нажатии Install в snap-store revision 1390 установка не начиналась.
Журнал содержит AppArmor DBus AccessDenied для
`org.freedesktop.PackageKit.CreateTransaction`. Отказ происходит до открытия
пакетной транзакции, поэтому это не ошибка maintainer scripts TypeTune.
Для проверки выбран штатный APT с графической авторизацией Polkit (`pkexec`);
политики AppArmor не отключаются и не расширяются. Подтверждение системной
установки фиксируется отдельно от успешных isolated-root тестов.

## Native подтверждение после ввода пароля

Пользователь подтвердил системную авторизацию. APT установил
`typetune-preview 0.1.0~preview51-1 amd64`, dpkg: `install ok installed`.
`package-configure` перевёл текущую checkout-установку на `/usr/lib/typetune-preview`.
Проверено полное равенство JSON settings/words/applications до и после миграции
без вывода их содержимого. Автозапуск переписан на packaged controller:
`autostart_effective=true`, `autostart_mismatch=false`.
GUI, runtime и transport запущены из системного payload. Desktop entry прошёл
`desktop-file-validate`. GNOME bridge v4 не менялся и доступен, для текущего сеанса
повторный вход не потребовался. Новая clean-user login, native upgrade/remove
и новый ввод в сторонних приложениях по-прежнему не приняты этой проверкой.
