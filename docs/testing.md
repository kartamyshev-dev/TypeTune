# Тестирование

## Уровни проверки

| Уровень | Что это | Где |
|---|---|---|
| Unit / fixtures | Engine, bridge, gesture, scoring, Swift helpers | CI, локально |
| Smoke | GTK-фикстуры, packaging checks | CI (Linux, Xvfb) |
| Package lifecycle | Сборка `.deb` / `.app`, checksum, codesign | CI |
| Native synthetic | Программные CGEvent в отдельном поле реального приложения, точный readback | Локально, с разрешениями macOS |
| **Native acceptance** | Живой физический ввод в приложениях | **Вручную**, не CI |

**Зелёный CI ≠ полная приёмка клавиатуры.** В CI нет физической клавиатуры и реальных TCC-диалогов.

## Что гоняет CI

- `cargo fmt` / `clippy -D warnings` / `cargo test --workspace`
- Python-тесты app / compat / packaging
- GTK smoke под Xvfb
- `scripts/test-macos.sh` (Rust engine/bridge + Swift Testing)
- Сборка и verify пакетов

### Регрессии цепочки macOS

`RuntimeIntegrationTests` соединяет настоящий `InputBuffer`, цикл `Runtime` и
Rust bridge с управляемыми временем, редактором и выводом. Эти тесты не посылают
события на рабочий стол. Они проверяют точные границы UTF-16, один/два пробела,
отставание AX, начало следующего слова, повтор Double Shift, Unicode перед
словом, отсутствие AX, отказ переключения, потерю наблюдения и неверный ACK.

`InputTransactionTests` проверяет очередь и состояние исполнителя с заменённым
системным транспортом; отдельные тесты проверяют физические коды и модификаторы
целевой раскладки. Проверки сроков различают общий бюджет операции 100 мс и
удержание не более 50 мс от первого перехваченного события: действует более ранний
срок, последующие события его не продлевают. `ObserverTransactionFlowTests`
проверяет освобождение очереди независимым watchdog без работы цикла Runtime
и запрет вывода после закрытия транзакции. Legacy AX-fixture сохраняют проверки
программного изменения каретки, точного снимка и readback; production HID backend
их не выполняет. Новые HID integration проверяют физические коды без early
Unicode, Enter без AX recovery, свежую историю нового приложения, потерю событий
при пустом/непустом batch, прямой session output и FIFO следующего слова.
Разрешения используются из контекста без повторного TCC RPC при удержании событий.

`SettingsTransactionTests` покрывает подтверждённое обучение,
очистку, конкурентные сохранения и восстановление после ошибок. Журнал в тестах
не должен писать данные в пользовательский каталог приложения.

Для нативной приёмки оба переключателя запускаются **по очереди**. Для каждого
сценария требуется 30 повторов с точным текстом, кареткой UTF-16, фактическим
input-source и длительностью. Программные CGEvent и физическая клавиатура —
разные строки приёмки. Состояние `submitted`, codesign и успешная сборка не
подтверждают исправление текста. Пропуски, повреждения и несовпадения с рабочим
сценарием Lang Switcher блокируют соответствующую строку приёмки.

Состояние работы и ограничения: [текущий macOS checkpoint](macos-input-stability.md).

## Корпус автокоррекции

- `crates/typetune-engine/data/auto-corpus.tsv` + baseline-метрики.
- Локально: `cargo test -p typetune-engine autocorrection_corpus`.
- Gate: ноль ложных срабатываний на negative-строках; пропуски фиксируются в baseline.

## Чего CI не закрывает

- Отзыв и повторную выдачу системных разрешений (macOS TCC).
- Secure Input, sleep/wake, lock/unlock.
- Игры, кастомные редакторы, удалённые сессии, elevated-приложения.
- Notarization / SmartScreen.
