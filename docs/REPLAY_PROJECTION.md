# Проекция вставок после replay

`ReplayInsertionProjection` — чистое ограниченное предсказание текста по обычным
вставкам, прошедшим replay tap. Это самостоятельное дополнение прототипа.
Оно не управляет FIFO, не повторяет события, не устанавливает AX-фокус и не
доказывает доставку в редактор. Причина наблюдавшегося пропуска второго слова
в Chrome пока остаётся гипотезой: возможны как неразобранный queued Space,
так и публикация AX-снимка до видимости replay в редакторе.

## API

```swift
var projection = ReplayInsertionProjection(
    anchorText: verifiedAfterMutation.text,
    selection: verifiedAfterMutation.selection
)
projection?.consume(.insertion("ghbdtn "))
projection?.consume(.keyUp)
projection?.consume(.modifierRelease)
projection?.invalidate(reason: .focusChanged)
```

Инициализация допускает только нулевое выделение на границе графемы. Максимум
исходного и предсказанного полного текста — 65536 единиц UTF-16. По умолчанию ограничены 2048 единиц
вставки и 64 завершённых токена. `expectedText`, `expectedSelection`,
`insertedRange`, `completedTokenRanges`, `hasUnfinishedTail`, `version` доступны
для проверки. Смена `version` означает изменение проекции, а не номер события.
После invalidation прежние свойства нельзя публиковать в кэш: проверка ниже
всегда вернёт false.

Обычная вставка здесь — явно нормализованный payload, который вызывающий код
уже отделил от команд, навигации, IME и paste. Поддерживаются печатные ASCII,
Space и русские буквы. Допускается несколько обычных символов в одном payload;
это не разрешение трактовать вставку буфера обмена как набор keydown. Пустой
payload, LF/TAB, emoji и combining/IME-последовательности инвалидируют проекцию.
Исходный снимок при этом может содержать emoji, NFD и любые другие символы.
Прочие действия вызывающий код передаёт через `invalidate`: Backspace/Delete,
навигацию, Command/Control/Option-команды, нажатия модификаторов/gesture,
смену поля, источника, разрешений или поколения операции.

Проекция завершает токен только на Space. Диапазоны относятся к предсказанному
полному тексту и целиком принадлежат новым вставкам. Если исходная каретка
стоит внутри/после незавершённого слова, первый продолжающий его фрагмент
учитывается в ожидаемом тексте, но не подлежит исправлению. После следующего
Space становятся допустимы последующие полностью вставленные слова. Существующие
слова по обе стороны каретки никогда не включаются в область обработки.

## Точная публикация кэша и исправления

```swift
let matches = projection.matchesObserved(
    text: observed.text,
    selection: observed.selection,
    ownsAnchor: exactRuntimeOwnership
)
let batch = projection.finish(
    observedText: observed.text,
    selection: observed.selection,
    ownsAnchor: exactRuntimeOwnership,
    decide: wholeTokenAutomaticEvaluator
)
```

`matchesObserved` проверяет exact UTF-16 и точную каретку, а не каноническую
Unicode-эквивалентность. Он нужен и при отсутствии завершённых слов: например,
`ghb` после seed `😀 ` не исправляется, но только полный `😀 ghb` разрешает
публикацию нового кэша. Нельзя публиковать первоначальный stale AX-снимок.

`ownsAnchor` обязан означать совпадение PID, AX-элемента, replay epoch/version,
источника ввода, разрешений, Secure Input и текущей ревизии; Core не может
самостоятельно установить эти факты. Последний ACK подтверждает проход tap,
а не изменение редактора. Вызывающий код может ограниченно ждать точного
предсказанного снимка, повторяя все проверки владения. Частичный снимок,
другую каретку или изменившееся поле нельзя принимать за успех.

`finish` при несовпадении не вызывает evaluator и не создаёт замену. Evaluator
принимает целый токен и возвращает обычный `Decision?`. Он должен использовать
существующую политику whole-token-first, затем допустимую trailing punctuation.
Если исправляется только префикс, callback обязан завернуть его в решение
для всего токена: `ghbdtn, → привет,`, с `original == "ghbdtn,"`.
Решение `original == "ghbdtn"` для такого токена отклоняется. Пустая замена,
управляющие символы и payload свыше 4096 единиц UTF-16 отклоняются; этот предел
действует и для общей замены, а итоговый полный текст не превышает 65536.
Это консервативный путь: control/format-символы в пользовательских правилах
также могут отключить aggregate-коррекцию. Нельзя вводить
отдельную эвристику, расходящуюся с основным автоматическим исправлением.

Результат `CorrectionBatch` содержит:

- `edit`: единый минимальный непрерывный диапазон от первого до последнего
  изменённого нового токена; разделители и промежуточные неизменённые слова
  сохраняются, замены строятся с конца;
- `decision`: исходный и новый текст этого диапазона; `reason` представляет
  последнее исправленное слово, полные решения доступны в `tokens`;
- `tokens`: только изменившиеся слова в порядке ввода;
- `undoLearning == .none`: отмена общей замены **не обучает** словарь фразой.

`decision.targetLanguage` равен nil при незавершённом вставленном хвосте или
неизменённом последнем завершённом токене. В остальных случаях берётся язык
последнего исправленного токена. Это ещё не разрешение менять TIS: runtime
также проверяет отсутствие новых событий. Каретка вычисляется через
`edit.resultingSelection(from: observed.selection)` — после оставшегося хвоста,
а не в конце исправленного диапазона.

## Runtime-интеграция — отдельная работа

Начальный anchor берётся только из подтверждённого after-mutation снимка.
При `.uncertain`, recovery либо неизвестном selection эффектах проекция
не создаётся. Событие учитывается ровно один раз на `InputReplayQueue.receive`
с disposition `.forward`; не при posting, `.retain`, `.suppress` или повторном
ACK. Инвалидация проекции отменяет только дополнительные исправления и
публикацию кэша — существующая FIFO-доставка/recovery остаётся неизменной.

Перед использованием плана runtime проверяет, что очередь полностью drained,
а поле, ревизия, epoch и version совпадают с отправленным на AX запросом.
Если за время чтения поступили новые события, сначала продолжается FIFO,
затем повторяется точная проверка; stale план не применяется. Передача плана
в существующий guarded mutate снова должна перепроверять текст/каретку.
Нельзя снимать gate и слепо применять снимок без привязки к этой ревизии.

Для undo необходимо явное поле метаданных транзакции с политикой `.none`.
Обычная однословная транзакция может сохранять прежнее обучение, но нельзя
вызывать `store.learn(batch.decision.original)` или автоматически обучать
каждое слово общей отмены. Статистика количества слов также берётся из
`tokens.count`, а не предполагает одну обычную коррекцию.

## Подготовленные проверки

`Sources/LayoutPilotCLI/ReplayProjectionChecks.swift` экспортирует
`replayProjectionChecks() -> [(Bool, String)]` для подключения к CLI selftest.
Проверки используют настоящий Core и Engine: несколько слов/пакетов и
незавершённый хвост; emoji/NFD prefix и существующий suffix; anchor внутри
слова; filenames/code/email и сохранение пунктуации через whole-token callback;
разную длину замен, точную каретку и обратимость aggregate undo; отсутствие
обучения; mismatch текста/каретки/владения без evaluator calls; stale AX;
keyUp/releases; unknown input, ограничения памяти/токенов и границы графем.

**На момент создания этих файлов сборка и тесты не запускались по указанию
координатора.** Эти проверки пока подготовлены, а не пройдены. Native приёмка
и причинная связь с Chrome stream20 не заявляются.

## Дополнение 16 октября: отдельная проверка маршрута FIFO

Runtime теперь запрашивает идентичность поля/окна/документа перед каждым
одиночным событием FIFO, не читая AXValue. На main/tap проверяется короткая
lease, привязанная к token/revision/source; отказ сохраняет очередь.
Устаревшие ACK не принимаются. Новые30 CLI queue/lease checks исполнены
в составе481/481, затем558/558 с ранним detector. Это не native-приёмка.
AX→доставка остаётся неатомарной. Отдельный review выявил устаревший recovery
anchor после частично доставленного префикса; исправление/проверка выполняются
перед следующим GUI-кандидатом и пока не объявлены принятыми.
