# Что можно взять из espanso

Изучено 2026-10-18: [espanso](https://github.com/espanso/espanso), коммит `0cadaea`
(2026-09-16), только macOS-часть и общий движок. Espanso распространяется под GPL-3.0:
берём только идеи, код не копируем. Всё ниже — **гипотезы для TypeTune**, ничего не
проверено ни offline, ни native.

Где смотреть в espanso:

| Что | Файл |
| --- | --- |
| Захват клавиатуры и мыши | `espanso-detect/src/mac/native.mm`, `mod.rs` |
| Отправка текста и клавиш | `espanso-inject/src/mac/native.mm` |
| Буфер набранного, сброс, Backspace | `espanso-engine/src/process/middleware/matcher.rs` |
| Ожидание отпускания модификаторов | `…/middleware/delay_modifiers.rs`, `espanso/src/cli/worker/engine/funnel/modifier.rs` |
| Отмена через Backspace | `…/middleware/undo.rs`, `action.rs` |
| Вставка через буфер обмена | `espanso/src/cli/worker/engine/dispatch/executor/clipboard_injector.rs`, `espanso-engine/src/dispatch/executor/text_inject.rs` |

## Где TypeTune уже не хуже

| Тема | espanso | TypeTune |
| --- | --- | --- |
| Захват | пассивный `NSEvent` global monitor: события не задерживаются | активный `CGEventTap` и барьер `MutationSession`: ввод во время правки задерживается и воспроизводится |
| Свои события | метка в координате мыши (`-27469`) | `eventSourceUserData` |
| Куда отправлять | `kCGHIDEventTap` (видят другие перехватчики) | `postToPid` с приватным источником |
| Unicode-события | части по 20 UTF-16 | части по 16 (`KeystrokeEditPlan.unicodeChunks`) |
| Backspace в буфере | откат к одному из 5 сохранённых состояний | `TypedWordBuffer.backspace()` без такого предела |
| Сброс буфера | стрелки, Home/End, PgUp/PgDn, Esc, клик | то же и Tab/Enter, ⌘/⌃/⌥, фокус, Secure Input, смена раскладки |
| Буфер обмена | сохраняется и восстанавливается только текст | все типы и проверка `changeCount` |
| Регистр в своих правилах | `propagate_case` | `Layout.matchingCase` |
| Переключатель на модификаторе | двойное нажатие; другая клавиша сбрасывает окно | Double Shift / оба Shift; `gestures.keyUsed()` |

## Что стоит взять

### 1. Ждать отпускания модификаторов перед правкой (риск для U8)

Espanso перед любой отправкой ждёт, пока отпущены ⌃⌥⌘⇧ (опрос раз в 100 мс,
не дольше 3 с), и отдельно отпускает Shift перед набором (issue #279: иначе
некоторые приложения печатали заглавные).

В TypeTune ⌘⌥Space и ⌘⌥Z срабатывают на нажатие Space/Z
(`KeyboardService.swift:339`), пока ⌘⌥ ещё физически зажаты. В универсальном режиме сразу после
этого уходят Backspace и Unicode-события (`KeystrokeEditor.perform`). У событий стоит
`flags = []`, но приложение, которое смотрит текущее состояние клавиш
(`NSEvent.modifierFlags`, `CGEventSourceFlagsState`), может прочитать их как ⌘⌫
(удалить строку) или ⌥⌫ (удалить слово). Double Shift срабатывает на отпускание,
поэтому его это не касается.

Предложение: в `runKeystrokes` перед `perform` ждать отпускания модификаторов. В коде
уже есть такая проверка для вставки без форматирования (`EditorSupport.nativePasteKeysReleased`,
`KeyboardService.swift:1368`). Ждать нужно внутри барьера и не на главном потоке, иначе
отключится event tap.

Проверка в U8: ⌘⌥Space в VS Code, Slack, Terminal и Word, удерживая ⌘⌥ около
полсекунды. Ожидание: исправлено только слово, строка цела.

### 2. Пауза между синтетическими событиями

На macOS espanso по умолчанию ждёт 1 мс после каждого нажатия и отпускания.
TypeTune отправляет все события подряд без пауз. Пока нет данных, что это теряет
символы. Предложение: если U8 покажет потери или перестановки (Electron, Java, Word),
добавить паузу отдельно для приложения, а по умолчанию оставить 0. Пауза тоже не должна
выполняться на главном потоке.

### 3. Показывать, какое приложение включило Secure Input

Espanso читает PID из IORegistry (`IOConsoleUsers` → `kCGSSessionSecureInputPID`),
по PID находит приложение и показывает уведомление. TypeTune пишет только
«Защищённый ввод включён» (`SettingsView.swift:81`). Частая причина — забытая
«Защищённая клавиатура» в Terminal или менеджер паролей. Если показать имя, например
«Защищённый ввод включил Terminal», пользователь поймёт, что выключить. Espanso
отмечает, что приложение определяется не всегда точно, поэтому формулировка
должна быть осторожной. Это чтение данных, правку текста оно не затрагивает.

### 4. Исключения по заголовку окна

В espanso правила можно привязать к приложению (`filter_exec`, `filter_class`) и к
заголовку окна по регулярному выражению (`filter_title`). В TypeTune исключения
задаются только по bundle ID. Риск «vim в обычном режиме, ssh» в универсальном
режиме можно закрыть исключением по заголовку: Terminal и iTerm показывают в нём
запущенную программу. Так же можно исключать отдельные сайты по заголовку вкладки.
Заголовок окна берётся через AX `kAXFocusedWindow` → `kAXTitle` или из
`CGWindowListCopyWindowInfo`.

### 5. Длинное или многострочное выделение — через вставку

Espanso набирает событиями текст до 100 символов, а длиннее — кладёт в буфер обмена,
нажимает ⌘V и через 300 мс возвращает прежнее содержимое. Многострочный текст при
наборе событиями он делит по `\n` и нажимает Enter между строками. В мессенджерах
Enter отправляет сообщение, поэтому так делать не стоит.

Сейчас TypeTune многострочное выделение не преобразует. Можно добавить вставку через
буфер обмена, используя уже готовое сохранение всех типов и проверку `changeCount`.
Восстанавливать содержимое нужно не сразу: приложение может прочитать буфер позже.
Это новая функция, её нужно согласовать с пользователем.

### 6. Отмена Backspace сразу после исправления — нужно решение пользователя

У espanso по умолчанию включено: если первое нажатие после замены — Backspace
(без мыши и другого ввода), замена откатывается к триггеру. В TypeTune для этого есть ⌘⌥Z
с обучением. Семантика Backspace конфликтует с обычным удалением пробела или буквы,
а поведение оригинала не установлено ([UNDO_RESEARCH](UNDO_RESEARCH.md)). Записано
как кандидат, без рекомендации внедрять.

### 7. Буфер обмена для менеджеров истории (не из espanso)

Espanso этого не делает. Есть соглашение [nspasteboard.org](http://nspasteboard.org):
если пометить запись типом `org.nspasteboard.TransientType`, менеджеры истории
(Maccy, Paste, Raycast) её не сохраняют. При восстановлении буфера после ⌘C
(`KeyboardService.swift:454`) пометка убрала бы дубль в их истории. Запись, которую
делает само приложение по ⌘C, пометить нельзя.

## Что не брать

- Пассивный global monitor и метку в координатах мыши: у TypeTune уже есть более надёжные механизмы.
- Отправку в HID tap и синтетическое отпускание Shift на уровне системы: это меняет общее состояние клавиш.
- Enter между строками при наборе.
- Подсчёт Backspace по Unicode scalar (`chars().count()`): TypeTune считает по набранным символам.
- Движок сниппетов, формы, поиск и пакеты: это другой продукт. Литеральные правила
  с сохранением регистра в TypeTune уже есть.
