Новый helper добавляет только счётчики неуспешных AX-атрибутов/кодов. Защита
по документу/полю/PID/Secure Input и бюджеты ожидания прежние. Текущий source SHA
записан в summary, прежний be4765… указан в deferred-candidate-identity.json.
Повторы с другой версией helper не считаются строгим сравнением с оригиналом.

Диагностика: AXFocusedWindow дважды и AXFocusedUIElement один раз вернули
-25204, то есть kAXErrorCannotComplete (проверено в локальном SDK AXError.h).
AXSubrole:-25205 — неподдерживаемый атрибут TextEdit, присутствует и в успешных
baseline; сам по себе это не причина остановки. Нельзя выводить из этих счётчиков
точный механизм задержки, причинность изменения TIS или потерю текста. Остановка
помощника означает прекращение следующей эмиссии. Частичный случай не принят.

Сохранены исходные JSON и completed checkpoints под research/evidence, личные
документы не использовались. Сырые Ghidra/оригинальные данные только в private.

После прерванного manual chord status-only обнаружил синтетические Command/Option.
Прототип и Lang Switcher остановлены; обычный ввод «a» в новом подтверждённом
документе снял флаги. Финальный status-only:0 событий, RussianWin, Secure Input
false, флагов Shift/Ctrl/Option/Command нет. Затем восстановлен Lang Switcher,
исходно работавший после перезагрузки; Caramba осталась остановленной как в начале.

Следующий шаг — диагностика app-side границы слова/ревизии без текста и отдельное
исследование AXCannotComplete. До устойчивого короткого native-набора длительный
прогон и новая упаковка не выполняются. Старый архив не перезаписывался.
