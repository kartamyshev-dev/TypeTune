# Типовые проблемы

## macOS: терминал показывает права, но приложение не работает

Прямой запуск исполняемого файла может использовать разрешения ответственного
родительского приложения. Для проверки установленной копии запустите doctor
через LaunchServices:

```sh
open -n -g -W -a /Applications/TypeTune.app \
  --stdout /tmp/typetune-doctor.json --args --doctor
cat /tmp/typetune-doctor.json
```

Если после ad-hoc обновления accessibility/listen/post стали false либо создание
обработчика ввода не удалось, удалите и заново добавьте точный путь текущей копии
в **обоих** разделах: «Универсальный доступ» и «Мониторинг ввода» macOS.
Простое выключение и включение существующей записи в проверенном случае сохраняло
привязку к старой подписи, хотя переключатели показывали разрешённый доступ.
Затем запустите TypeTune и проверьте живой обработчик; отдельный doctor не
подтверждает его работу.

## Не срабатывает Double Shift / авто-правка

1. Приложение запущено? (macOS — иконка в строке меню; Linux — tray.)
2. Нет ли **Паузы** / «Все выключено»?
3. macOS: выданы Input Monitoring и Accessibility **текущей** копии приложения?
4. Linux: после Setup был **перелогин**?
5. Приложение не в списке исключений? (Авто выключается, жест должен работать.)
6. Не secure/парольное поле?
7. Включено **Ручное переключение** для Double Shift, **Автопереключение** для Space и обе нужные **Активные раскладки**?

## macOS: после пересборки пропали разрешения

Ad-hoc подпись привязывает designated requirement к CDHash исполняемого файла.
После изменения бинарного файла прежний grant может не соответствовать новой
сборке. Включённый переключатель macOS сам по себе этого не обнаруживает.

1. Завершите установленный TypeTune через меню. Уточните его фактический путь; для текущей установки это `/Applications/TypeTune.app`. Распакованных старых `.app` с тем же bundle ID рядом быть не должно.
2. Откройте Настройки macOS → Конфиденциальность и безопасность → **Универсальный доступ**. Выделите прежнюю запись TypeTune и удалите её кнопкой «−».
3. Нажмите «+», укажите **точно `/Applications/TypeTune.app`**, добавьте его и включите разрешение.
4. Выполните то же **удаление и добавление** в разделе **Мониторинг ввода**. Простого переключения off/on недостаточно для исправления старого `csreq`.
5. Запустите именно установленную копию. Проверьте doctor через LaunchServices по команде выше: правильный `bundle_path`, идентичность сборки и `listen`/`post`/`accessibility`. Затем проверьте `observer_started` в свежей диагностике GUI-процесса и реальную коррекцию в тестовом поле.

Если приложение намеренно установлено в `~/Applications`, на шагах 1–5 везде
используйте этот точный путь. В подтверждённом восстановлении удаление и повторное
добавление в обоих разделах обновило привязку TCC к текущей подписи и позволило
GUI-процессу запустить наблюдение; это ещё не приёмка всех сценариев коррекции.

Дальнейший путь для обновлений — постоянная сертификатная code-signing identity,
чей designated requirement сохраняется между сборками, при неизменном bundle ID.
Возможная настройка сборщика — `TYPETUNE_CODESIGN_IDENTITY` с идентификатором уже
подготовленного сертификата. **Сейчас такая переменная не поддерживается:**
`build-macos.sh` явно использует `codesign --sign -`. Простое задание переменной
не меняет подпись и не гарантирует сохранение grants. Создание сертификата,
изменения Keychain и проверка перехода на постоянную подпись — отдельная работа;
обычное обновление не выполняет её и не редактирует TCC.

## macOS: безопасное обновление

Завершите TypeTune через меню и выполните из корня репозитория:

```sh
bash scripts/build-macos.sh --install /Applications/TypeTune.app
```

Без явного пути скрипт сначала выбирает существующую `/Applications/TypeTune.app`, затем `~/Applications/TypeTune.app`; новая установка создаётся во втором месте. Запускайте установку от пользователя приложения. Скрипт удерживает его `instance.lock` и отказывается заменять пакет работающего процесса. Копирование и проверка подписи идут в скрытом каталоге без дополнительного `.app`; обмен готового пакета атомарный. До замены прежняя копия сохраняется в `~/Library/Application Support/TypeTune/backups/TypeTune.rollback-*.zip`: архив распаковывается для проверки подписи и точного совпадения содержимого, затем получает права `0400` в каталоге `0700`. Ошибка архивации запрещает замену; ошибка итоговой проверки запускает откат. Настройки остаются в каталоге пользователя.

Не храните распакованный старый `TypeTune.rollback-*.app` рядом с установленным приложением: LaunchServices регистрирует тот же bundle ID, и macOS может связать новое разрешение со старой подписью. Это уже наблюдалось при включённых переключателях разрешений и отказе создания event tap. Резервные копии должны оставаться ZIP-архивами; после устранения дубликатов разрешения выдаются через обычные настройки macOS единственной установленной копии. Сам установщик TCC и базу LaunchServices не изменяет.

Для ручного восстановления распакуйте проверенный ZIP во временный каталог вне `/Applications` и передайте извлечённый `TypeTune.app` команде `python3 scripts/macos-package.py install ПУТЬ_К_КОПИИ /Applications/TypeTune.app` после завершения приложения. Старую копию из временного каталога запускать не нужно.

При ошибке подписи, прав доступа или отката не запускайте случайную копию пакета: сохраните сообщение ошибки и проверьте путь установленного приложения. Для сборок, прерванных по времени, полный вывод находится в `target/macos-build.*/<фаза>/phase.log`, для тестов — в `target/macos-test.*/<фаза>/phase.log`. Тайм-аут завершает только собственную группу процессов после сбора диагностики; такая сборка не считается успешной.

## Linux: Setup требует пароль / не ставится из GNOME Software

Локальный `.deb` удобнее ставить так:

```sh
sudo apt install ./typetune_*.deb
```

После настройки доступа к устройствам — перелогин.

## Linux: слово пропало после клика мыши / Caps Lock / смены раскладки

Начиная с 0.1.3 эти случаи **не** должны сбрасывать текущее слово:

- клик мыши / касание — отменяют только незавершённый Double Shift;
- Caps Lock / Fn — latch, не chord;
- Super+Space / Caps как переключатель раскладки — слово сохраняется, пропускается одно авто-слово.

Если поведение повторяется — проверьте, что в трее актуальная версия (`typetune-preview --status`).

## Linux: нет флага раскладки в трее

- «Показывать флаг раскладки» включено?
- Источник ввода — обычный XKB `us`/`ru` (иные раскладки показывают `?`).
- Панель может кэшировать иконку: переключите раскладку или перезайдите в сеанс.

## «Результат неизвестен»

Правка могла выполниться частично (фокус сменился, приложение съело символы). История сброшена, повтор **не** запускается. Проверьте текст глазами и наберите слово заново при необходимости.

## macOS: «Отправлено, не проверено» / «Не исправлено: контекст изменился»

`submitted` означает, что отправка завершилась. Начиная с 0.2.7 macOS HID backend не читает итоговый текст через AX: результат необходимо проверить в редакторе. Это сохраняет работу в редакторах без читаемого AX-текста, но не является доказательством правильного текста и не добавляет постоянные выученные слова.

`rejected` означает отказ до вывода: например, изменилась ревизия ввода, приложение-получатель, разрешения или раскладка. Разрыв наблюдения запрещает замену неполного слова до известной границы. Текст, набранный до запуска или после потерянных событий, через AX не восстанавливается. Не повторяйте автоматически неизвестную правку; сначала проверьте текст.

## Не то слово исправляется

- Добавьте форму в **исключения**.
- Или выключите **Автопереключение** и оставьте Double Shift.
- Короткие слова и имена собственные по умолчанию защищены; если слово часто нужно «перекладывать» — используйте жест.

## Другой язык / раскладка

В настройках **Активные раскладки** укажите источники ввода, которые считать EN и RU. Неизвестная раскладка показывается как `?` и не участвует в авто-правке.

## Диагностика

- macOS: `/Applications/TypeTune.app/Contents/MacOS/TypeTune --doctor` (либо тот же путь в `~/Applications`) — JSON с версией, commit/dirty/digest исходников, путями пакета и исполняемого файла, PID, разрешениями, источником ввода и login-item. Команда не запускает наблюдение; `live_observer_status=unavailable_separate_process` честно означает, что состояние tap другого процесса не проверено.
- Linux: `typetune doctor --session` (JSON: протокол, ОС, `/dev/input`, `uinput`, раскладка, автозапуск).
- Linux: `TYPETUNE_DIAG=1` у runtime пишет `~/.local/state/typetune/diag.log` — только решения (invalidate, helper-lost, trigger), без набранного текста.
- macOS: `~/Library/Application Support/TypeTune/diag.log` — результаты `verified|submitted|rejected|indeterminate`, причины отказа, длительности и счётчик потерянных диагностических записей. Отдельные клавиши, набранные слова и clipboard не записываются. Очередь ограничена, запись идёт отдельно от ввода; журнал до 1 МиБ + одна ротация, права `0600`.
- macOS: прежний журнал при первом запуске новой версии переносится в `diag-legacy-*.log` с правами `0600`. Он может содержать старую поклавишную диагностику; это локальный материал, который не следует публиковать без проверки.
- Linux: `./scripts/typetune-test status`.
- Нативное окно: `typetune-gui` → раздел «Разрешения и состояние».
