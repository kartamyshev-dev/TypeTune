# 42 — Двухбуквенные слова

2026-09-16. Пользователь запросил автокоррекцию двухбуквенных слов, например
`,s` → «бы». Base commit `18f366ed58ddb08799e527f0d4599a0bcf513f29` + этапы 40–42.

## Контракт

После Space длина 2 допускается при цели в top-100 частотного словаря.
Длина 3 по-прежнему требует top-1000, 4–32 — top-20000 или pilot.
Однобуквенные слова автоматически не исправляются. Это эвристика, не оценка
вероятности: без контекста нельзя гарантировать отсутствие ложных замен.
Известный исходный token имеет приоритет независимо от частоты цели: `ye`
(«ну»), `vs` («мы»), `lf` («да») сохраняются, доступны через Double Shift.

`,s` → «бы», `<s` → «Бы», `<S` → «БЫ», `yt` → «не», `jy` → «он»;
обратное направление: `ещ` → `to`, `шт` → `in`. Запятая на US является
клавишей русской «б» и не завершает историю. Space учитывается один раз.
Общий matcher обслуживает IBus и compatibility; прежние context guards сохранены.

## Проверки и установка

TWO-42: старый matcher воспроизвёл отказ `,s`; после изменения 22 текстовых
случая проверяют controlled editor/fake clock, текст, каретку, anchor,
префикс/суффикс, направление и inferred parity. Три отказа дополнительно
проверяют Unknown focus/composition и selection до редактирования.
Python fixture проверяет evdev-коды comma/S/Space, историю `,s `, применение
keyboard plan с сохранением текста/каретки и отсутствие удержанных клавиш.

118 Rust tests и 13 compatibility + 23 IBus Python tests прошли.
Среда Ubuntu 26.04.1, Rust 1.98.1. Новая native GUI приемка не проводилась.
[Evidence](evidence/42-two-letter.txt). Preview обновлён, активный compatibility
runtime перезапущен. Для пользовательской проверки: US, `,s`, Space → `бы `,
дальнейший ввод RU. Проверка физического ввода остаётся за пользователем.
