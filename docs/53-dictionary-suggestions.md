# 53 — предложения автокоррекции после ручных исправлений

Base: `9831bb8bab16df4b128594f226e8a325cdc9f52b`, локальные изменения.
Ubuntu 26.04.1, GNOME 50.1 / Wayland, GTK 4.22.4.

## Поведение

Окно переименовано в «Предложения для словаря». Существующие предложения
«Не исправлять» после трёх отмен автозамены сохраняются. Новый вид — «Исправлять»:
после трёх отдельных ручных исправлений одного слова предлагается добавить
целевую форму в пользовательские слова. Только кнопка «Добавить» сохраняет её
и применяет через общий controller / ReloadWords с проверкой generation.

После этапа 55 пробел можно нажать до или после Double Shift. Если пробел уже
был, завершённая ручная замена засчитывается сразу; иначе — после следующего пробела. Дописывание букв к тому же слову не считается подтверждением.
Повторный Double Shift на том же вхождении отменяет обучение этого вхождения,
включая отзыв уже засчитанного случая и ещё не принятого предложения.
Backspace, навигация, shortcut, смена контекста и неуспешный output сбрасывают
ожидающее подтверждение. Трижды переключать одно слово недостаточно.

Сбор включён только при разрешённой автокоррекции для текущего приложения.
Проверяется, что действующие правила не исправляют слово, а добавление целевой
формы действительно разрешит эту замену. Проверка использует тот же Rust engine
с временным словарём в памяти и восстанавливает его до исполнения замены.
Известное правильное исходное слово, явные исключения, лимит словаря и защитные
правила не обходятся. Уже добавленные слова повторно не предлагаются.

Счётчики двух видов разделены; общий предел — 64 пары. Они и предложения живут
только до перезапуска. Слова не попадают в status/logs; отдельный GetSuggestions
возвращает их только для явного просмотра. Подтверждение сохраняет остальные
слова и исключения; конфликт со свежим исключением возвращает ошибку.

## Проверка пользователем

С включённой автокоррекцией в не исключённом редакторе: EN → `nbgn.y` →
Double Shift → «типтюн» → пробел. Повторить на трёх новых вхождениях.
Открыть «Предложения для словаря» и подтвердить «Исправлять».
Затем `nbgn.y` + пробел должно автоматически стать «типтюн ».
Тестовое слово можно удалить в «Слова и исключения».

## Роль IBus на момент этапа 53

В следующем [этапе 54](54-remove-ibus.md) этот adapter удалён; описание ниже историческое.

IBus — альтернативный ограниченный adapter для клиентов с surrounding-text API.
Для основного compatibility-профиля он не требуется как активный режим. Однако
общий ABI-движок, controller, GUI и настройки исторически размещены в каталогах
с названием ibus. Удаление режима требует сначала отделить общие компоненты,
затем убрать engine registration, зависимости пакета, mode UI/IPC и их тесты.
В этом этапе IBus не удалён.
