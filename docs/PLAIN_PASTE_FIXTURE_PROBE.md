# Ограниченный помощник проверки plain paste

`Tools/PlainPasteFixtureProbe.swift` предназначен только для уже открытой
страницы Chrome `http://127.0.0.1:18763/?fixture=LP-CODEX-001` и её полей
`LP-CODEX-001 plain` / `LP-CODEX-001 rich`. Другие вкладки и поле переписки
не допускаются. Помощник активирует имеющийся Chrome один раз; новую страницу
или документ он не создаёт. Перед запуском оператор открывает нужное поле.

Сборка без выполнения:

```sh
scripts/plain_paste_fixture_probe.sh --compile-only
```

Запуск после проверки нужного тестового поля и состояния переключателя:

```sh
scripts/plain_paste_fixture_probe.sh
scripts/plain_paste_fixture_probe.sh --expect passthrough
scripts/plain_paste_fixture_probe.sh --native-match-style --source hid
```

Оба режима ожидают один и тот же синтетический plain text
`первая\nвторая\tстрока`, курсор UTF16 в конце и пустое выделение.
`--expect passthrough` только подписывает сценарий, когда оператор отключил
обработчик LayoutPilot/его plain-paste функцию. Сам помощник настройки не меняет
и по совпадению текста не утверждает, какой обработчик выполнил вставку.
`--source private|hid` выбирает CGEventSource (по умолчанию private).
`--native-match-style` выбирает Cmd+Option+Shift+V вместо Cmd+Shift+V, чтобы
отдельно проверить системную команду Chrome Paste and Match Style. Присутствие
этого флага не является доказательством обработки команды без native-проверки.

Допускается только пустое поле (включая AX `\n` пустого contenteditable) либо
ровно ранее вставленный синтетический текст с возможным конечным LF. Перед
вставкой выбирается известное синтетическое содержимое; личный текст не удаляется.
Снимок читается только после проверки PID, текущего поля/окна, точного label
и URL в пределах 20 предков. AX trust, CGEvent posting, Secure Input, фокус и
clipboard changeCount повторно проверяются перед каждым событием.
До начала требуются нейтральные flags и отпущенные физические левые/правые
Cmd/Shift/Option/Control, CapsLock/Fn по hidSystemState и combinedSessionState.

В clipboard временно помещаются собственные plain и RTF представления одного
текста. Исходные items/types/data сохраняются только в памяти (до64MiB;
недоступное представление или смена поколения прерывают опыт до записи).
Восстановление выполняется лишь при неизменном собственном changeCount;
последующая проверка сравнивает исходные типы и байты в памяти. Если пользователь
изменил clipboard, его новое содержимое не перезаписывается и результат не PASS.
Операции NSPasteboard не атомарны относительно внешних клиентов; проверки
changeCount ограничивают окно гонки, не заявляют системную транзакцию.

Выдаётся ограниченный кадр из6 HID-событий по образцу `NativeProbe.tap`:
Cmd down, Shift down, V down/up, Shift up, Cmd up. Modifier-события имеют тип
flagsChanged и соответствующие device-side/aggregate bits; отпускания идут
в обратном порядке. Return и строковые Unicode/control payload не выдаются.
С `--native-match-style` кадр состоит из8 событий: между Cmd и Shift добавлены
Option down/up с device-side0x20, отпускания также в обратном порядке.
Новые сторонние модификаторы прерывают кадр; чужие физические клавиши помощник
не отпускает. При отказе guard нет слепого cleanup в другое поле. Одновременное
физическое нажатие той же клавиши, которую держит synthetic frame, нельзя
надёжно отличить по aggregate keyState; во время короткого опыта не вводить
с клавиатуры. После0,8сек проверяются текст/курсор и нейтральность flags/keyState.
Неожиданный текст скрывается; содержимое, типы и хеши исходного clipboard никогда
не попадают в stdout, файл или журнал. JSON содержит только известный
синтетический результат, числовой курсор, AX-коды ошибок и булевы guards/clipboard.

Exit0 означает совпавшие text/cursor, нейтральные модификаторы, неизменность clipboard при вставке и
проверенное восстановление исходного clipboard. Exit1 — остановка по guard;
exit2 — несовпадение результата/сохранности. Это ограниченный native helper,
а не полная приёмка F07, форматирования или обработки в Codex.

**Проверка при добавлении:** компиляция Swift5 прошла. Native-запуск помощника
автором этого файла не выполнялся; runtime PASS отсутствует. GUI приложения
не пересобирался и не менялся.

## Расширение контроля форматирования

Помощник теперь добавляет собственное HTML-представление с bold/red/19px вместе
с plain и RTF. `--formatted-control` выдаёт только CmdV (4 события), конфликтует
с `--native-match-style`. Собственная [страница](../Tools/fixtures/chromium/index.html)
показывает наличие b/strong/i/em/font/style-узлов rich-поля; отсутствие таких
узлов не является общим доказательством отсутствия любого CSS. В проверенном
контроле CmdV индикатор present, production plain paste — absent. Курсор, текст,
clipboard и состояние приложения проверяются отдельно.

`--neutral-only` проверяет точный fixture/permissions и сообщает только состояния
модификаторов; не пишет selection/clipboard и не выдаёт клавиши.
`--hold-past-timeout` держит собственные Cmd/Shift2.3с после V-up и ожидает
неизменные текст/выделение вместо вставки; отпускания всё равно проходят прежние
guards. Несовместим с formatted-control/native-match-style. На отказе сохраняются
только номер собственного кадра, type/key и коды уже проверяемых modifier keys;
Unicode/clipboard пользователя не записываются. Диагностика не ослабляет stop.

Воспроизводимая страница находится в Tools/fixtures/chromium/index.html.
`scripts/serve_chromium_fixture.sh` запускает только loopback18763; затем открыть
точный fixture URL в отдельной Chrome-вкладке. Не запускать второй сервер на
том же порту. Текущий исследовательский сервер использует идентичную копию в private.
