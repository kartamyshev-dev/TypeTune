# Инструкция для агента на Mac: native-проверка исправлений и универсального режима

Документ для агента, который работает **на Mac пользователя**. Выполняй шаги строго по порядку.
Не пропускай проверки и не меняй ожидания под результат. Общение и записи — по-русски.
Прежде чем начать, прочитай `AGENTS.md`: его правила главнее этого документа.

## 0. Что проверяется и почему

После релиза v0.1.3 код менялся без единой native-проверки. Его собирали и проверяли
только на Linux и в CI на macOS. Нужно проверить один конкретный коммит в двух режимах:

- **Часть A — прежний строгий путь** (`universalInput = false`): исправления по ревью
  (пунктуация, двойные заглавные, пауза, словарь, барьер ввода) в TextEdit.
- **Часть B — универсальный режим** (`universalInput = true`, значение по умолчанию):
  правка нажатиями Backspace во всех приложениях. В TextEdit — через NativeProbe,
  в остальных приложениях — вручную пользователем.

Проверяемый код — ветка `universal-input` ([план](UNIVERSAL_INPUT_PLAN.md),
[решения](DECISIONS.md), пп. 21–27). Ветка содержит весь `main` плюс универсальный режим.
Поэтому один проверенный коммит, в котором универсальный режим выключается, позже
можно слить в `main` перемоткой (fast-forward), и результаты будут относиться ровно к нему.

## 1. Жёсткие правила (из AGENTS.md и истории проекта)

1. **NativeProbe** (`Tools/NativeProbe.swift`) разрешён только для **новых локальных
   тестовых документов TextEdit**, которые он создаёт сам. Не направляй синтетический ввод
   в другие приложения. Для них предусмотрен ручной сценарий (раздел 6) или отдельное явное
   разрешение пользователя, записанное в журнал.
2. Перед каждым событием проверяются документ, поле, PID, разрешения и Secure Input.
   Эти проверки нельзя ослаблять ради результата.
3. **Одновременно работает только один переключатель раскладки.** Caramba Switcher Pro,
   Lang Switcher и другие копии TypeTune должны быть завершены: это проверяет
   `selected_switcher_pid`.
4. После ad-hoc пересборки macOS может отозвать разрешения. Обновлять нужно **только запись
   TypeTune** в «Универсальный доступ» и «Мониторинг ввода» через системный UI. Это делает
   пользователь; ты просишь и ждёшь. Затем приложение перезапускается.
5. В конце восстанови исходное состояние: раскладку, настройки TypeTune, установленное
   приложение, состояние оригинала Caramba.
6. PASS не переносится между коммитами и видами проверки. Каждый результат записывай с SHA
   коммита, SHA-256 исполняемого файла и видом проверки.
7. Не добавляй в Git бинарники, `research/private`, данные Caramba и тексты пользователя.
8. Все коммиты — от `kartamyshev <vs.kartamyshev@gmail.com>`. Push — только в
   `universal-input`. **В `main` не сливай без явного решения пользователя.**
9. Остановись и спроси пользователя, если:
   - упала любая проверка из разделов 2–5;
   - NativeProbe остановился с ошибкой;
   - замечена потеря или порча текста;
   - нужно действие в UI (разрешения, переключатели) или работа вне TextEdit.

## 2. Подготовка

```sh
cd <твой клон TypeTune>            # у пользователя ранее: ~/git/caramba, remote kartamyshev-dev/TypeTune
git fetch origin
git switch universal-input
git pull --ff-only
git config user.name kartamyshev
git config user.email vs.kartamyshev@gmail.com
git rev-parse HEAD                  # запиши: это проверяемый коммит
git status --porcelain              # должно быть пусто
swift --version                     # нужен Swift 6.x
scripts/ci_core.sh                  # офлайн-проверки: должен завершиться с exit 0
scripts/runtime_recovery_probe.sh   # должен вывести "passed": true
```

Если `ci_core.sh` или пробник не прошли, остановись и сообщи пользователю.

Заведи каталог evidence с датой: `E=research/evidence/mac-native-$(date +%Y-%m-%d)`,
`mkdir -p $E`. Приватные копии клади в `P=research/private/mac-native-$(date +%Y-%m-%d)`.

## 3. Снимок исходного состояния (для восстановления)

```sh
mkdir -p $P
defaults export dev.layoutpilot.mac $P/defaults-before.plist          # настройки TypeTune
ditto /Applications/TypeTune.app $P/TypeTune-before.app                 # если установлен
shasum -a 256 /Applications/TypeTune.app/Contents/MacOS/LayoutPilot > $P/installed-before.sha256
ps -axo pid=,comm= | grep -E 'Caramba|Lang ?Switcher|LayoutPilot|TypeTune' > $P/switchers-before.txt || true
defaults read com.apple.HIToolbox AppleSelectedInputSources > $P/input-source-before.txt
```

Запиши в `$E/state-before.json` без самих настроек: какие переключатели были запущены,
текущую раскладку, SHA установленного приложения, включён ли автозапуск TypeTune.
Если Caramba запущена, попроси пользователя завершить её. Сам её не трогай.

## 4. Сборка и установка проверяемого коммита

```sh
scripts/build.sh                                   # release arm64, ad-hoc подпись, dist/LayoutPilot.app
dist/layoutpilot-cli selftest                      # 1412/1412
osascript -e 'quit app "TypeTune"' || true          # завершить прежний экземпляр
ditto dist/LayoutPilot.app /Applications/TypeTune.app
codesign --verify --deep --strict /Applications/TypeTune.app
shasum -a 256 /Applications/TypeTune.app/Contents/MacOS/LayoutPilot | tee $E/installed.sha256
```

Попроси пользователя:
1. В «Системные настройки → Конфиденциальность и безопасность» удалить и снова добавить
   **TypeTune** в «Универсальный доступ» и «Мониторинг ввода».
2. Запустить `/Applications/TypeTune.app`.
3. Подтвердить, что подсказка флага в строке меню показывает «Работает».

Запиши `$E/installation.json`: коммит, SHA, вывод `codesign`, подтверждение пользователя.

Одновременно должен работать ровно один переключатель. Проверка:
`ps -axo pid=,comm= | grep -E 'Caramba|LayoutPilot|TypeTune'` должен показать одну строку.

## 5. Часть A — прежний строгий путь (TextEdit, NativeProbe)

Выключи универсальный режим: Настройки TypeTune → снять «Исправлять во всех приложениях».
Это может сделать пользователь, или ты, если он разрешит. Проверь, что под переключателем
появилась подпись про TextEdit, Chrome и Codex.

Запусти по очереди. Каждый файл — отдельный запуск, каждый вывод — новый файл.

```sh
APP=/Applications/TypeTune.app
python3 scripts/record_native_probe.py --app $APP --output $E/A-smoke.json --batch corpus/native-smoke.json
python3 scripts/verify_native_suite.py $E/A-smoke.json --fixtures corpus/native-smoke.json > $E/A-smoke.verification.json

python3 scripts/record_native_probe.py --app $APP --output $E/A-review.json --batch corpus/native-review-fixes-v1.json
python3 scripts/verify_native_suite.py $E/A-review.json --fixtures corpus/native-review-fixes-v1.json > $E/A-review.verification.json

python3 scripts/record_native_probe.py --app $APP --output $E/A-stream80.json --batch corpus/native-stream-80ms-v1.json --interval-ms 80
python3 scripts/verify_native_suite.py $E/A-stream80.json --fixtures corpus/native-stream-80ms-v1.json > $E/A-stream80.verification.json
```

**Отмена с обучением** (`corpus/native-review-undo-v1.json`) меняет сохранённые настройки:
добавляется выученное слово `ghbdtn`. Запусти её так же (`A-undo.json`), затем:
- попроси пользователя удалить `ghbdtn` из выученных слов: Настройки → у слова кнопка «Снова исправлять»;
- сверь `defaults export dev.layoutpilot.mac -` с `$P/defaults-before.plist`.
  Различаться может только `universalInput`.

**Пауза** (`corpus/native-pause-v1.json`) использует жест «оба Shift». Попроси пользователя
включить «Левый + правый Shift — пауза автоисправлений». Запусти `A-pause.json`, затем
попроси вернуть переключатель в исходное положение.

Ожидаемо: в каждом `*.verification.json` поле `"failures": []` и
`"fixtureIdentityVerified": true`; `verify_native_suite.py` при расхождении завершается с кодом 1. Любой другой результат — остановка (правило 9).

Ручные пункты части A. Их выполняет пользователь в новом документе TextEdit, а ты
записываешь результат в `$E/A-manual.json`:
1. Набрать `ghbdtn`, прокрутить окно колесом мыши, набрать пробел. Ожидание: «привет ».
2. Набрать `ghbdtn vbh`, выделить мышью перетаскиванием, нажать Shift дважды. Ожидание: «привет мир».
3. Набрать быстро без пауз `ghbdtn vbh ghbdtn vbh `. Ожидание: все слова исправлены,
   порядок символов не нарушен.

## 6. Часть B — универсальный режим

Включи «Исправлять во всех приложениях» (значение по умолчанию).

### 6.1 TextEdit через NativeProbe

Повтори все команды раздела 5 с префиксом `B-` вместо `A-`: smoke, review, stream80,
undo, pause. Ожидания те же: универсальный путь должен давать тот же текст, курсор
и раскладку. Обратите внимание на статус в строке меню: в TextEdit поле читается через AX,
поэтому должно быть «Текст исправлен», а не «…без проверки поля».

### 6.2 Остальные приложения — вручную пользователем

NativeProbe сюда не направлять (правило 1). Для каждого приложения пользователь делает
шаги ниже в новом пустом поле, а ты записываешь в `$E/B-apps.json` строку
`{app, version, step, result, status_text}`, где `status_text` — подсказка флага
в строке меню после шага.

Приложения: Заметки, Safari (страница и адресная строка), Google Chrome (страница
и адресная строка), Telegram, Slack, VS Code, Microsoft Word, Codex, Terminal (zsh),
Terminal (vim, режим вставки). Если приложения нет — запиши «нет».

Шаги для каждого приложения:
1. Раскладка ABC. Набрать `ghbdtn ` → «привет », раскладка русская.
2. Раскладка русская. Набрать `руддщ ` → «hello », раскладка английская.
3. `ghbdtn/ ` → «привет. ».
4. Клик мышью в середину существующего слова, затем `ghbdtn `. Ожидание: если статус
   «…без проверки поля», то ничего не исправлено; если поле читается — исправлено,
   только если перед словом пробел.
5. Набрать `ghbdtn`, нажать Shift дважды → «привет».
6. Выделить слово мышью, нажать Shift дважды → слово преобразовано.
   В приложении, где выделение не читается: заранее скопировать в буфер обмена картинку,
   выполнить шаг, затем вставить ⌘V. Ожидание: вставляется картинка, буфер обмена восстановлен.
7. После шага 1 нажать ⌘⌥Z → вернулось `ghbdtn `, раскладка прежняя. Снова набрать
   `ghbdtn ` → не исправляется. После проверки — «Снова исправлять» у этого слова в настройках.
8. Одиночный Shift переключает раскладку (флаг в строке меню меняется).
9. Быстро набрать `ghbdtn vbh ghbdtn vbh ` → всё исправлено, порядок не нарушен.

Отдельно:
- **Автозамена macOS** (Заметки, TextEdit): включить «Исправлять ошибки автоматически»,
  набрать слово с опечаткой и пробел. Ожидание: лишний текст не стёрт. Если поле
  читается, допустимо «Исправление пропущено: текст поля не совпал с набранным».
- **Подсказки:** в адресной строке Chrome и Safari набрать начало адреса, который
  браузер дополняет. Ожидание: дополнение не испорчено.
- **Пароли:** поле пароля в Safari; `sudo -v` в Terminal. Ожидание: TypeTune ничего не делает.
- **Выключенный режим:** снять «Исправлять во всех приложениях» → в Заметках
  исправлений нет, в TextEdit они есть.

Если после любого шага текст испорчен, остановись. Попроси пользователя сохранить
технический отчёт: Настройки → «Сохранить отчёт…»; текста в отчёте нет.
Положи отчёт в `$P`, а в `$E` — только сводку фаз `universal-begin` /
`universal-verify` / `universal-result` и их флагов.

## 7. Восстановление исходного состояния

1. Удали выученные тестовые слова, если они остались. Сверь настройки с
   `$P/defaults-before.plist`.
2. Попроси пользователя вернуть исходное положение переключателей, которые менялись
   (пауза обоих Shift, «Исправлять во всех приложениях», автозамена macOS).
3. Если до проверки был установлен другой TypeTune и пользователь хочет его вернуть:
   завершить TypeTune, затем `ditto $P/TypeTune-before.app /Applications/TypeTune.app`
   и снова обновить разрешения через системный UI.
4. Верни исходную раскладку (`$P/input-source-before.txt`).
5. Если до проверки была запущена Caramba, попроси пользователя запустить её. Двух
   переключателей одновременно быть не должно.
6. Запиши `$E/state-after.json` и отличия от `state-before.json`.

## 8. Запись результатов

1. `$E/verification.json`:
   - коммит, SHA приложения;
   - для каждого запуска: вид проверки (`native TextEdit, NativeProbe` или
     `user manual`), файл случаев и его SHA, результат;
   - что не запускалось (`NOT_RUN`) и почему.
2. В `docs/JOURNAL.md` новая запись сверху, по образцу существующих: что, каким видом
   проверки и с каким результатом.
3. `docs/STATUS.md`:
   - заполни таблицу «Что проверено» для этого коммита;
   - обнови точку продолжения.
4. `docs/PLAN.md` — закрой этапы 4, 5, 7 по результатам части A.
   `docs/UNIVERSAL_INPUT_PLAN.md` — закрой U8 только при полном прохождении части B.
   Частичный результат — открытый пункт со ссылкой на evidence.
5. Найденные расхождения:
   - оформи как fixtures (`corpus/native-*.json` для TextEdit, описание для ручных);
   - если причина в ядре — добавь регрессию в selftest;
   - исправление делай отдельным коммитом;
   - после любого изменения кода повтори разделы 2, 4 и затронутые проверки на новом
     коммите. Прежние PASS к нему не переносятся.
6. Коммить и делай push в `universal-input`. Сообщи пользователю итог: что прошло,
   что упало, что NOT_RUN, и можно ли сливать в `main`. Решение о слиянии — за ним.

## 9. Быстрая справка

| Вопрос | Ответ |
| --- | --- |
| Где настройки | `defaults read dev.layoutpilot.mac`, ключи `settings.v1` (JSON), `universalInput`, `earlyCorrection` |
| Где диагностика | `~/Library/Application Support/LayoutPilot/Diagnostics/stability-*.json` (только коды этапов) |
| Формат случая NativeProbe | `id`, `text` (ASCII 32–126, до 128 символов), `source` (`ABC`/`RussianWin`), `gesture`, `boundary`, `expected`, `expectedSource`, `expectedSelection` |
| Проверить случаи до запуска | `scripts/native_probe.sh --validate-cases --batch <file>` |
| Статусы универсального режима | «Текст исправлен» (AX подтвердил), «Текст исправлен без проверки поля» (поле не читается), «Исправление пропущено: текст поля не совпал…» (расхождение), «Проверьте последний текст» (отправлено, но не подтверждено) |
| Что точно не работает | многострочное выделение; раннее исправление в универсальном режиме |
