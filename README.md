# TypeTune

Проект кроссплатформенного помощника ввода: коррекция RU/EN раскладки, Unicode-сниппеты и опциональный антидребезг клавиш.

**Текущий статус — ранний Linux-прототип с подтверждёнными критическими дефектами.** На 2026-09-10 рабочая поддержка Linux, Windows и macOS не заявлена. Аудит ревизии `8cc19d0` объясняет причины и задаёт новую архитектуру; код приложения в этом документационном этапе не исправлялся.

## Что уже есть

Rust workspace из 11 crates: core, input, inject, layout, chatter, corrector, snippets, config, CLI, tray и GTK GUI. Есть TOML-конфигурация, таблицы RU/EN, словарные файлы, D-Bus интерфейс, systemd/deb-заготовки и CI.

Это полезные наработки, но наличие модулей не означает готовность функций. Сейчас raw keycodes преобразуются неверно, repeat становится release, остановка не подключена к event loop, текстовые стадии не получают символы. Изолированные проверки обнаружили дополнительные ошибки удаления текста, Unicode и состояния буферов. Hot reload не применяет новую конфигурацию к действующему pipeline.

## Новый подход

Опциональный Linux hardware filter отвечает за физические клавиши и устойчивость транспорта. Отдельный session engine наблюдает текст, формирует план замены и выполняет его через платформенные адаптеры. Обычный ввод сразу доходит до приложения. Раскладка, фокус, модификаторы, происхождение событий и доступные возможности входят в явные контракты.

Начальный порядок: проверяемое ядро и identity relay → ранняя проверка Wayland-возможностей → статические сниппеты и ручная коррекция → автоматическая коррекция → Windows/macOS adapters → полноценная оболочка и установка. Готовность каждого backend-а подтверждается отдельно.

## Проверка переносимой части

Из корня workspace, при установленном Rust:

```bash
cargo test --locked -p typetune-core -p typetune-chatter -p typetune-config -p typetune-corrector -p typetune-snippets
```

На baseline команда успешно собирает эти библиотеки, но выполняет **0 тестов**. Полный workspace на текущем macOS-хосте не прошёл проверку из-за отсутствующего `pkg-config` для native dependencies; это не результат Linux-сборки.

Инструкции запуска с эксклюзивным захватом основной клавиатуры и автозапуском вынесены из quick start: текущий прототип ещё не прошёл transport/shutdown gates. Требования к изолированному Linux-стенду находятся в [плане проверки](docs/14-development-plan.md).
